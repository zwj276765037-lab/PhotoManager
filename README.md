# PhotoManager（AI 动态人生杂志）

基于微信小程序的 AI 动态杂志海报生成项目。

当前阶段：根据用户初衷，产品已调整为“从短视频或 GIF 捕捉真实动态，生成一张首尾可无缝衔接的动态杂志海报”。`goal/README.md` 已进入 v0.5 待审核稿，业务代码将在本轮需求审核通过后进入 `workspace/`。

## 目录约定

```text
PhotoManager/
├── goal/       # 项目需求、功能范围、验收标准、上线说明
├── mission/    # 每一次优化的时间、内容、验证结果和提交记录
└── workspace/  # 微信小程序、云函数/后端和测试代码
```

三个目录的职责不能混用：

- `goal/` 回答“要做什么、做到什么程度”。
- `mission/` 回答“何时做了什么、是否验证通过”。
- `workspace/` 存放“实际运行的代码”。

## 最底层工作方式

用户主动选择一段短视频或一个 GIF，小程序负责素材预览、高光确认和轻量编辑；云端负责运动分析、主体分层、杂志版式、循环编排和 MP4 渲染。第一版采用以下数据流：

```text
用户选择/拍摄短视频，或选择一个 GIF
        ↓
私有上传与输入内容安全检查
        ↓
AI 为视频推荐高光；短 GIF 默认保留完整动作
        ↓
AI 生成主体分层、杂志版式和短文案
        ↓
生成 3 个与素材兼容、具有结构性差异的动态候选
        ↓
用户调整片段、焦点、标题、速度和动态强度
        ↓
服务端渲染 1080 × 1350 首尾闭环 MP4 与 JPG 封面
        ↓
保存到相册后发布朋友圈或其他社交平台
```

底层数据分为三部分：

1. 私有临时文件：源视频/GIF、代理视频、主体蒙版和预览，按明确期限自动清理。
2. 动态海报计划：高光片段、落版帧、循环方式、主体轨迹、版式、文字、字体和颜色，可用于恢复任务和确定性重渲染。
3. 输出文件：服务端生成的首尾闭环短 MP4 与静态 JPG 封面，通过短期地址下载后保存；是否自动重播由发布平台决定。

MVP 优先采用微信小程序前端、私有对象存储、异步媒体任务、运动分析和 FFmpeg 确定性渲染。AI 密钥只保存在服务端；高级分割不可用时仍可降级为受规则约束的动态封面，不能退化为视频矩形加边框。

## 每次成果的交付规则

每一轮修改都按以下顺序完成：

1. 在 `goal/` 确认或更新需求与验收标准。
2. 只在 `workspace/` 修改项目实现。
3. 完成与变更风险相匹配的检查或测试。
4. 在 `mission/` 追加日期、优化内容、验证结果和未解决问题。
5. 提交 Git，并推送到 `origin/main`：<https://github.com/zwj276765037-lab/PhotoManager>。

这里的“覆盖到 GitHub”定义为：GitHub 的 `main` 分支是最终成果基线，每次成果都提交并正常推送。默认不使用强制推送，以免误删远端历史；只有明确要求重写历史且确认备份后才会执行。
