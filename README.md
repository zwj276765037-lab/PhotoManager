# PhotoManager（AI 人生杂志）

基于微信小程序的 AI 人生杂志生成项目。

当前阶段：产品已从普通方格拼图进一步调整为“AI 人生杂志”。`goal/README.md` 已进入 v0.4 待审核稿，业务代码将在本轮需求审核通过后进入 `workspace/`。

## 目录约定

```text
PhotoManager/
├── goal/       # 项目需求、功能范围、验收标准、上线说明
├── mission/    # 每一次优化的时间、内容、验证结果和提交记录
└── workspace/  # 微信小程序、云函数/后端和测试代码
```

三个目录的职责不能混用：

- `goal/` 回答“要做什么、做到什么程度”。
- `mission/` 回答“何时做了什么、是否验证通过”。
- `workspace/` 存放“实际运行的代码”。

## 最底层工作方式

用户主动选择 4～12 张照片，小程序负责选图、三页低清预览和轻量编辑；云端 AI 负责精选照片、确定叙事、生成文案与版式计划，渲染器输出封面、故事、结尾三张高清页面。第一版采用以下数据流：

```text
用户选择 4～12 张照片并填写可选主题
        ↓
私有上传与输入内容安全检查
        ↓
AI 摄影编辑精选 4～8 张并规划叙事
        ↓
AI 艺术指导与文案编辑生成杂志方案
        ↓
生成 3 套“封面 + 故事 + 结尾”低清候选
        ↓
用户换图、调整裁切、版式和文字
        ↓
服务端渲染三张 1080 × 1440 高清页面
        ↓
保存整套后按顺序发布朋友圈
```

底层数据分为三部分：

1. 私有临时文件：用户原图、中间稿和预览图，按明确期限自动清理。
2. 杂志计划：三页叙事、照片角色、裁切焦点、版式、文字、字体和颜色，可用于恢复任务和确定性重渲染。
3. 输出文件：服务端生成的三张高清杂志页，通过短期地址下载后按顺序保存。

MVP 优先采用微信小程序前端、私有对象存储、异步任务服务和确定性服务端渲染。AI 密钥只保存在服务端，生成服务不可用时仍可降级为受规则约束的三页杂志版式，不能退化为平均方格拼图。

## 每次成果的交付规则

每一轮修改都按以下顺序完成：

1. 在 `goal/` 确认或更新需求与验收标准。
2. 只在 `workspace/` 修改项目实现。
3. 完成与变更风险相匹配的检查或测试。
4. 在 `mission/` 追加日期、优化内容、验证结果和未解决问题。
5. 提交 Git，并推送到 `origin/main`：<https://github.com/zwj276765037-lab/PhotoManager>。

这里的“覆盖到 GitHub”定义为：GitHub 的 `main` 分支是最终成果基线，每次成果都提交并正常推送。默认不使用强制推送，以免误删远端历史；只有明确要求重写历史且确认备份后才会执行。
