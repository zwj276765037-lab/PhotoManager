# PhotoManager iOS 动态人生杂志 App 需求

> 版本：v0.6-draft
>
> 状态：已确认原生 iOS Live Photo 读取进入首发 P0，详细范围待审核
>
> 更新时间：2026-08-29
>
> 本轮主题：以 iOS 原生 App 读取完整 Live Photo，从真实动态中生成仍会动的杂志封面

## 1. 用户初衷与产品定位

目前常见照片应用要么只做静态拼图，要么把 Live Photo 降级成静态照片或普通视频，再增加边框、滤镜和贴纸，缺少一种能保留真实动态并把它编辑成“会动的杂志封面”的产品。

本项目首发形态调整为 iOS 原生 App。用户可以直接选择一张原生 Live Photo，App 使用 PhotoKit 读取其静态照片与配对 MOV，并把二者作为同一个动态资产处理；也可以选择普通视频或 GIF。AI 从真实动态中找到最有表现力的片段和落版画面，再完成主体分层、杂志构图、刊头、标题、色彩和首尾闭环节奏，最终输出适合朋友圈及其他社交平台的动态杂志封面。

一句话主张：

> 不是给动态素材套模板，而是把这一刻编成会动的杂志封面。

“一张图”在这里描述的是视觉体验：它看起来是一张完整的竖版杂志封面，用户可以选择经过首尾闭环设计的短 MP4、GIF 动态图片或两者，同时附带一张静态 JPG 封面。首发 P0 保证读取原生 Live Photo，但不承诺把编辑结果重新封装成系统 Live Photo；该输出能力单独进入后续验收。文件本身不能强制社交平台重复播放，只有在支持循环的播放器中才会连续循环。

## 2. 产品不是什么

- 不是把多个视频平均放入方格。
- 不是在普通视频外面增加纸张边框。
- 不是让原视频从头到尾在矩形窗口里播放。
- 不是依靠滤镜、贴纸、慢推和淡入淡出伪装成“AI 风格”。
- 不是生成模型重新绘制人物动作或面容。
- 不是复杂的多轨视频剪辑软件。

AI 的核心角色是“动态主编”：选择高光片段、确定落版帧、理解主体运动、设计主体与文字/版心的关系，并让动作最终回到一张可阅读的杂志封面。

## 3. 核心术语

| 名称 | 定义 |
| --- | --- |
| 原生 Live Photo | iOS 照片资料库中的一个 `PHAsset`，至少包含静态照片资源与 `pairedVideo` 配对视频资源 |
| 动态源 | 用户主动选择的一张原生 Live Photo、一段短视频或一个 GIF；每个任务只处理一个动态源 |
| 高光片段 | AI 推荐的、适合被编辑成循环海报的 2～5 秒动作片段 |
| 落版帧 | 动态开始与结束时呈现的完整杂志封面画面，也是静态封面来源 |
| 动态主视觉 | 页面中承担主要动作和第一视觉中心的区域 |
| 动态杂志海报 | 视觉上是一张杂志海报、实际以首尾可无缝衔接的 MP4 或 GIF 交付的最终作品 |
| 结构模式 | 动态封面、主体破版、时间切片等空间和时间组织方式 |
| 视觉风格 | 字体、色彩、刊头、线条、文案语气和材质组成的设计系统 |

## 4. MVP 输入与输出

### 4.1 输入

MVP 每次处理一个动态源：一张原生 iOS Live Photo、一段短视频或一个 GIF。三类输入在完成原始资源读取后进入同一时间轴、动态分析和渲染流程。

原生 Live Photo 要求（首发 P0）：

- 通过系统照片选择器让用户明确选择单个 Live Photo，不扫描或静默读取整个照片库。
- 使用 PhotoKit 根据 `PHAsset.localIdentifier` 获取资源清单，并至少识别一份静态照片资源和一份 `.pairedVideo` 资源。
- 静态资源优先保留原始 HEIC/JPEG；动态资源保留原始 MOV，不使用屏幕录制、预览缩略图或转成普通视频后再作为输入。
- 两个资源必须绑定同一个内部 `sourceId`，分别记录资源类型、原始文件名、UTType、字节数、像素、时长、校验和与本地资产标识；禁止把不同资产错误配对。
- 对只在 iCloud 中的资源允许联网下载，展示真实进度，并支持取消、失败重试和重新选择；下载完成前不能显示“导入成功”。
- 若资源缺失、损坏、无法下载或配对校验失败，明确说明原因；不能只取静态首帧后假装 Live Photo 已成功导入。
- App 仅在用户确认生成后上传所需原始资源；上传到云端前移除与生成无关的 GPS、设备等元数据，本地相册原件不被修改或删除。
- 首发验收覆盖当前仍受 Apple 支持的主流 iOS 版本和真实设备；最低系统版本在技术原型验证后冻结。

短视频要求：

- 来源：手机相册选择或直接拍摄。
- 原视频时长：3～30 秒。
- MVP 硬上限：100 MB；超过后先提示用户裁短或在系统中压缩，不直接上传。上限可根据真机和后端压力测试下调。
- 支持方向：横屏或竖屏，后端统一处理方向和色彩空间。
- 直接拍摄普通视频时由原生相机入口限制最长 30 秒；从照片资料库选择后仍需重新读取媒体信息并校验时长。

GIF 要求：

- 从相册作为图片选择后上传原文件。
- 时长建议 2～10 秒、文件不超过 50 MB、总帧数不超过 300 帧。
- 服务端根据文件头和实际帧数识别，不能只依赖扩展名。
- 选择后不能先经过 Canvas、图片压缩或重新编码，避免只保留静态首帧。
- 若 iOS 照片资料库或文件选择器只返回静态版本，必须提示用户改用视频，不能宣称已经获得动画。
- 2～5 秒 GIF 默认使用完整动画，只需确认落版帧和首尾闭环方式，不强制挑选 3 个高光。
- 超过 5 秒的 GIF 进入同一动态源时间轴，由系统推荐 1～3 个动作完整的片段，用户也可保留整段或手动调整。

三类输入都可以附带可选主题、一句话、日期和视觉风格，全部可以跳过。

普通视频与 GIF 是兼容输入，不取代原生 Live Photo 主路径。Android 各厂商 Motion Photo 格式不进入 iOS 首发版本。

### 4.2 输出

每次生成 3 个具有结构性差异的低清候选。系统只使用与当前素材兼容的结构模式，不为凑齐模式牺牲质量；用户选择一个后可以导出“视频 MP4”“动态图片 GIF”或同时导出两种格式，不需要重新分析素材或重新生成版式。

共同规格：

- 成片比例：4:5 竖版。
- 成片时长：4～8 秒，默认 6 秒。
- 两种动态格式使用相同片段、落版帧、首尾闭环、版式和文字。
- 始终附带 1 张 1080 × 1350 JPG 静态封面。

MP4 视频输出：

- 尺寸：1080 × 1350。
- 帧率：24 或 30 fps，由渲染器统一，不沿用异常可变帧率。
- 视频编码：H.264 High、`yuv420p`、BT.709，写入 `faststart`。
- 音频：MVP 默认静音，不复制原视频语音。
- 默认使用“高清优先（high）”编码；另提供“节省空间（standard）”档。
- 文件大小目标：15 MB 以内，最终按画面复杂度动态控制码率。

GIF 动态图片输出：

- 标准尺寸：720 × 900；高清 GIF 是否开放取决于体积和真机测试。
- 帧率：12 或 15 fps。
- 最多 256 色，不宣称与 MP4 等画质。
- 文件大小目标：15 MB 以内；超限时先降低帧率或尺寸并让用户确认。
- 默认静音；GIF 格式本身不支持音频。

是否自动播放、重复播放以及使用哪一帧作为平台封面，由朋友圈或其他社交平台决定，产品不能承诺。

### 4.3 输出格式与清晰度原则

- 用户可以按用途选择 GIF 或 MP4，输入格式不限制输出格式。
- MP4 是“清晰优先”推荐项，适合人物、渐变、夜景、文字和朋友圈视频发布。
- GIF 是“动态图片兼容”选项，但只有 256 色，同等观感下通常体积更大，平台也可能压缩或只显示首帧。
- 视频输入生成 MP4 时必须从原始视频或高质量规范化输入直接渲染，不能先转 GIF 再转回视频。
- GIF 输入必须先完整解帧，再生成高质量内部时间轴；最终可分别编码为 MP4 或 GIF。
- 不进行无意义的多次转码；预览代理不得作为高清输出源。
- MP4、GIF 与 JPG 应从同一个无损或等效高质量版式母版分别编码，GIF 不得先经过有损 MP4 再导出。
- 输入规范化必须按原始宽高比、方向和主体焦点计算裁切，并只做一次高质量缩放；高分辨率源不得先固定降到 720 像素再放大输出。
- 720 像素宽的源画面放大到 1080 像素只改变输出尺寸，不会产生真实新细节。系统必须在低分辨率、低码率、夜景运动模糊或放大比例过高时提示“清晰度受原素材限制”。
- “高清优先”使用高质量缩放和较低压缩强度，减少二次损失；锐化只能适度使用，不能把光晕、噪声或伪细节冒充清晰度。

因此，默认推荐 MP4，但 GIF 输出正式进入 MVP，并由用户在结果页选择。

## 5. 首发平台与分享边界

### 5.1 iOS 原生 App 是首发编辑端

- 首发采用 Swift/SwiftUI 原生 iOS App，照片资产访问使用 PhotoKit，视频读取与本地预览使用 AVFoundation/AVKit。
- 请求照片权限前展示用途说明；优先使用系统选择器和有限照片访问，只处理用户明确选择的资产。
- 原生 Live Photo 是首发主入口，普通视频和 GIF 是兼容入口。
- App 负责选择、原始资源读取、配对校验、本地预览、编辑交互、任务恢复、下载和保存。
- 云端负责高成本动态分析、主体分层、版式规划、内容安全与确定性高清渲染；后续可依据性能和隐私评估把部分能力迁移到端侧。
- 微信小程序不负责原生 Live Photo 采集，因为 `wx.chooseMedia` 不返回完整静态照片、配对 MOV 和可供 PhotoKit 使用的资产标识。
- 后续小程序只作为已生成作品的登录、预览、任务状态和分享引导入口，不是首发阻塞项。

### 5.2 保存和分享

- 使用系统照片资料库写入能力保存 MP4、GIF 或 JPG；写入权限被拒绝时说明用途并提供前往系统设置的入口，不能反复弹窗。
- 使用 iOS 系统分享面板分享本地导出文件；目标应用是否接收 GIF、是否压缩 MP4、是否只显示首帧，由目标平台决定。
- 朋友圈稳定主路径仍是“保存 MP4 到系统相册 → 用户打开朋友圈并选择视频发布”。
- App 不承诺静默、自动或一键替用户发布朋友圈，也不把分享面板成功弹出等同于发布成功。
- GIF 保存到系统相册后必须重新读取并验证是否仍含多帧；若目标平台降级为静态图，明确推荐 MP4。
- JPG 是静态封面，不被描述为动态输出。
- 朋友圈中的自动播放、重复播放、封面选择、压缩和裁切均由微信客户端决定；项目只保证导出文件自身首尾可无缝衔接，并通过真实发布测试记录平台表现。

其他社交平台默认以“保存 MP4 后由用户上传”为通用路径；GIF 是否保持动画需按目标平台真机验证。

## 6. 结构模式与视觉风格必须分开

结构模式决定“画面怎样动”，视觉风格决定“杂志长什么样”。如果两者混在一起，3 个候选很容易退化为同一模板换颜色。

MVP 建议构成一个 3 × 3 的受控组合空间：3 种结构模式 × 3 种视觉风格。AI 先排除不适合当前素材的结构，再挑选 3 个结构性差异最大的候选，不需要把 9 种组合全部展示给用户，也不强制一次覆盖全部 3 种结构。

## 7. 三种首发结构模式

### 7.1 动态封面

- 视频或关键帧占据主要版面，可以满版或使用非矩形遮罩。
- 刊头、大标题和栏目文字与主体形成前后层次。
- 动作展开时，主体可以经过刊头、穿过文字留白或跨越版心。
- 首尾回到完整落版封面，暂停时依然像一本杂志。

适合：人物转身、回头、行走、挥手、宠物动作、风景变化。

### 7.2 主体破版

- 先以落版帧建立静态杂志构图。
- 将人物、宠物、车辆或其他运动主体分割出来。
- 动态主体可以越出版心、压住刊头、穿过色块或在前后景之间运动。
- AI 只保留真实像素和真实动作，不补画或重绘人物。
- 分割质量不足时自动降级为安全整图动态封面。

适合：人物动作明确、背景相对稳定、主体轮廓清晰的视频。

### 7.3 时间切片

- 从同一动作中提取 2～4 个关键时间相位。
- 使用不等宽切片、延迟回声、局部定格或动作轨迹表现时间经过。
- 页面只有一个主动态，其余相位是静态、弱动态或延迟回声。
- 禁止把切片做成等宽方格或普通胶片九宫格。

适合：跳跃、舞动、奔跑、转身、抛物、运动和有明确动作轨迹的片段。

### 7.4 结构适用门槛

- 主体破版只有在主体分割、边缘质量和运动跟踪均达标时才能进入候选池。
- 时间切片只有在动作轨迹清晰、各时间相位可辨且不会产生错误肢体关系时才能进入候选池。
- 风景变化、镜头移动或主体不明确的素材优先使用动态封面。
- 同一素材可以产生多个动态封面候选，但动态区域、前后层级和时间编排必须形成结构性差异。
- 安全降级方案仍必须通过“非视频套框”四项否决门槛，不能变成全屏视频叠标题。

## 8. 三种首发视觉风格

### 8.1 先锋刊头

- 黑、白、信号红或高对比配色。
- 粗无衬线刊头、超大标题、克制的小字栏目。
- 适合人像、动作、时尚和强视觉内容。

### 8.2 人文特刊

- 暖中性色、米白、墨黑和低饱和照片。
- 宋体与无衬线组合，纪实注释和短引文。
- 适合家人、生活、宠物和自然动作。

### 8.3 城市画报

- 冷灰、钴蓝或建筑色彩。
- 窄体字、竖向栏目眉、建筑式切割和细线。
- 适合街拍、旅行、夜景、展览和城市运动。

每套视觉风格需要定义字体授权、字重、颜色、刊头、栏目、文字语气、版心、安全区和装饰规则，而不仅是一个滤镜。

## 9. 完整用户流程

```text
打开 iOS App，点击“捕捉一个会动的封面”
        ↓
选择一张原生 Live Photo、一段 3～30 秒视频或一个 2～10 秒 GIF
        ↓
PhotoKit 读取并校验原始照片与 pairedVideo；普通视频/GIF 校验原文件
        ↓
私有上传与输入内容安全检查
        ↓
AI 分析清晰度、镜头稳定性、主体、人脸与运动轨迹
        ↓
Live Photo/视频推荐高光；短 GIF 默认使用整段，长 GIF 推荐 1～3 个片段
        ↓
用户确认默认片段，或展开时间轴调整起止点与落版帧
        ↓
填写可选主题、一句话、日期和视觉风格
        ↓
AI 生成文案、结构模式、空间版式与时间编排
        ↓
生成 3 个与素材兼容、具有结构性差异的低清动态候选
        ↓
用户选择并进行轻量编辑
        ↓
用户选择 MP4、GIF 或两者，并生成 JPG 封面
        ↓
输出内容安全复检与适用的 AI 标识
        ↓
保存到系统照片资料库 / 调用系统分享面板
        ↓
用户发布到朋友圈或其他社交平台
```

## 10. AI 动态捕捉

### 10.1 动态源质量分析

AI 分析：

- 视频方向、分辨率、帧率、码率和时长。
- 模糊、过曝、欠曝、黑帧和镜头剧烈抖动。
- 人脸与主要物体位置。
- 主体运动幅度、方向、速度和轨迹。
- 可用于刊头与标题的低信息区域。
- 首尾画面是否适合形成自然循环。

AI 不保存人物身份特征，不根据外表推断身份、关系、职业或其他敏感信息。

### 10.2 高光片段与整段使用策略

对于 Live Photo 和普通视频，系统推荐最多 3 个高光片段，每个片段长度 2～5 秒；不足 3 个合格片段时不强行补齐。系统默认选中评分最高的一个，其他建议折叠为“换一个瞬间”，避免让用户连续做两轮复杂选择。

对于 GIF：

- 2～5 秒时默认使用完整动画，用户直接确认落版帧和首尾闭环方式。
- 超过 5 秒时推荐 1～3 个动作完整的片段，也允许用户保留整段。
- GIF 解帧后与视频使用同一动态源时间轴、质量评分、落版帧和渲染流程。

高光评分不能只看运动幅度，还应综合：

- 主体清晰度。
- 动作完整度。
- 构图安全区。
- 镜头稳定性。
- 人脸与关键动作可见性。
- 首尾循环可行性。
- 与用户主题的非敏感视觉匹配度。

用户可以接受默认选择、展开其他推荐，也可以在时间轴上手动微调起止点。若没有合格片段，系统需要明确建议更换素材或手动选择，不能硬套低质量模板。

### 10.3 落版帧

AI 为每个片段推荐一个落版帧：

- 暂停时主体清晰、表情和动作完整。
- 有足够区域放置刊头与标题。
- 能作为循环的开始与结束状态。
- 单独导出为 JPG 时仍是一张成立的杂志封面。

用户可以拖动时间轴更换落版帧。

### 10.4 循环方式

根据素材选择：

- 自然闭环：原动作首尾位置接近，直接对齐循环。
- 交叉过渡：短时间混合首尾，隐藏轻微差异。
- 往返循环：动作正向后平滑反向，适用于部分非周期动作。
- 落版回收：动作结束后通过遮罩或版式变化回到落版状态。

不能为了循环产生明显鬼影、倒放违和、黑帧或主体瞬移。用户可以预览循环后再确认。

## 11. 六秒标准时序示例

```text
0.0–0.6 秒  完整落版封面，刊头和标题可阅读
0.6–3.2 秒  主体从静态层中运动，与刊头/版心发生层次关系
3.2–4.8 秒  动作高潮，以一次时间切片或局部强调呈现
4.8–6.0 秒  动作回落并恢复到与首帧一致的落版状态
```

不同模板可以改变节奏，但都必须包含“可阅读的落版 → 动态展开 → 回到落版”的闭环。

## 12. 杂志空间版式硬规则

1. 暂停在首帧或落版帧时，必须独立成立为一张杂志海报。
2. 每个作品只有一个第一视觉中心。
3. 禁止 2×2、3×3、等宽分栏和居中视频矩形加边框。
4. 动态主视觉建议占页面 55%～85%，明显大于辅助定格画面。
5. 必须包含刊头、主标题，以及栏目/日期/图注中的至少一种辅助信息。
6. 最多使用 2 套字体、3 个字重和 4 级字号。
7. 至少使用一种深度编辑关系：主体压字、字压主体、破版、前后景遮挡、时间切片或非矩形动态遮罩。
8. 单纯滤镜、缩放、纸张边框、贴纸和淡入淡出不算深度编辑关系。
9. 画面必须保留可读的负空间或低信息区域。
10. 人脸、眼睛和关键动作不得被文字或裁切无意遮挡。
11. 关键主体与标题尽量位于中部 1:1 安全区域，兼顾社交平台缩略图裁切。
12. 装饰不能比真实动作更抢眼，也不能生成未经授权的品牌 Logo。
13. 标题建议 4～12 字，副标题 10～24 字，图注可关闭。
14. 不根据人物外表编造关系、地点、经历或情绪事实。

## 13. 动态时间编排硬规则

1. 成片 4～8 秒，开头与结尾回到同一落版状态。
2. 1 秒内必须出现主要动态，不能长时间只显示静态封面。
3. 同一时间最多 1 个主动态区和 1 个弱辅助动态区。
4. 主标题和刊头在大部分播放时长内保持可读。
5. 文字动画只使用克制的遮罩、错位或轻微位移，禁止频繁跳动。
6. 动作必须与版式发生关系，不能只在固定矩形内播放。
7. 不能只靠全画面慢推、淡入淡出、滤镜或转场制造动态感。
8. 避免频闪、快速抖动和过多转场，优先保留真实动作节奏。
9. 首尾不能出现黑帧、硬跳、明显重影或主体瞬移。
10. 分割、跟踪或循环置信度不足时使用安全降级或要求重选。
11. 静态封面、首帧和结束帧必须使用相同落版设计。
12. MVP 默认静音，避免原声隐私、循环断点和社交平台自动播放差异。

## 14. 防止退化为“视频套框”的四项否决门槛

每个候选和最终作品都必须通过：

1. 暂停测试：隐藏播放控件，落版帧仍被认为是一张杂志封面。
2. 结构测试：至少有一种主体、文字与版心的深度关系；只有外框、贴纸或滤镜直接淘汰。
3. 时间测试：运动具有“落版 → 展开 → 回落”的编排，不是原视频从头播到尾。
4. 候选差异测试：任意两个候选必须使用不同的兼容结构模式，或在使用同一模式时同时改变版式层级与时间编排；不能只换颜色、字体或滤镜。

任一门槛不通过时，方案不能进入用户候选列表。

## 15. 页面与功能需求

### 15.1 首页

- 主入口：“捕捉一个会动的封面”。
- 示例自动静音循环，首帧显示完整杂志封面。
- 示例明确区分动态封面、主体破版和时间切片。
- 提供最近草稿和最近作品。
- 首次使用说明 Live Photo 的照片与配对视频、普通视频或 GIF 会私有上传并由云端分析。

### 15.2 动态源选择与检查

- 从系统照片选择器选择一张 Live Photo、一段视频或一个 GIF；普通视频也可直接拍摄。
- 对 Live Photo 明确显示“原生动态照片”，读取其静态照片和配对 MOV，并显示 iCloud 下载、配对校验和导入进度。
- 显示输入类型、时长、大小、方向、帧数、清晰度和格式检查。
- 视频超过 30 秒时提示先裁剪，不能直接进入生成。
- GIF 超过时长、大小或帧数限制时提示转换为视频。
- Live Photo 缺少任一成对资源、资源损坏或 iCloud 下载失败时明确说明原因，不得静默降级为静态照片。
- 其他不支持、损坏或只有一帧的素材明确说明原因。
- 不读取用户未选择的其他视频或照片。

### 15.3 动态源时间轴

- 显示 Live Photo 配对视频、普通视频或 GIF 解帧后的统一时间轴，并用 Live Photo 静态资源作为落版帧候选之一。
- Live Photo/视频显示最多 3 个 AI 高光建议；2～5 秒 GIF 默认选中完整动画；较长 GIF 显示 1～3 个建议。
- 默认方案直接首尾衔接预览，其他高光折叠为“换一个瞬间”。
- 用户可以拖动起止点、选择落版帧和调整主体焦点。
- 片段过短、过长或无法循环时实时提示。
- 用户确认片段后再进入风格生成，减少无效推理。

### 15.4 本期信息与风格

可选字段：

- 主题。
- 一句话。
- 日期。
- 结构偏好，或交给“AI 动态主编”。
- 视觉风格，或智能推荐。

所有 AI 文案都可编辑、隐藏或单独重新生成。用户不提供信息时，只能生成中性文案，不编造具体事件。

### 15.5 三个动态候选

- 三个候选使用低清代理视频首尾衔接预览。
- 每个候选显示结构模式、视觉风格、片段和文件生成预估。
- 任意两个候选使用不同的兼容结构模式，或在同一模式下同时改变主体/文字层级和时间编排。
- 用户可以收藏候选、换一批、锁定片段后重排或进入编辑。
- 换一批不得覆盖已收藏候选和用户文字。

### 15.6 轻量编辑器

用户可以：

- 在当前 Live Photo/视频可用的高光建议之间切换，使用短 GIF 完整动画，或微调起止点。
- 更换落版帧。
- 调整主体焦点与安全裁切。
- 编辑或关闭刊头、标题、日期和图注。
- 在当前结构内切换 2～3 个安全版式变体。
- 更换字体组合和配色。
- 选择慢、标准、快三档动作速度。
- 调整低、中、高三档动态强度。
- 锁定已确认片段后只重新生成文案或版式。
- 撤销最近一步并恢复 AI 初始方案。

MVP 不提供任意元素拖动、复杂关键帧、多轨时间线、贴纸商城和音乐编辑器。

### 15.7 结果页

- 在 App 播放器中连续预览高清成片的首尾衔接效果。
- 选择“视频 MP4”“动态图片 GIF”或“两种都要”，切换格式不重新生成版式。
- 保存 MP4 到系统相册。
- 下载或保存 GIF；若真机验证发现系统只保留首帧，则明确提示改用 MP4。
- 保存 JPG 静态封面。
- 使用系统分享面板分享 MP4/GIF/JPG；若用户安装微信，可由用户选择其支持的目标入口。
- 显示每种格式的尺寸、帧率、预计体积、清晰度说明和平台兼容性提示。
- 继续编辑或只重试失败的高清渲染。
- 删除本次 Live Photo 云端副本或其他源素材、中间文件和结果；不删除系统照片资料库原件。
- 清楚提示“朋友圈请先保存视频，再从朋友圈选择发布”。

## 16. 技术工作方式

```text
iOS App 通过系统选择器获得用户明确选择的 PHAsset
        ↓
PhotoKit 读取 Live Photo 原始照片 + pairedVideo；或读取普通视频/GIF 原文件
        ↓
本地资源配对、完整性、媒体参数与校验和检查
        ↓
中国区私有对象存储
        ↓
输入内容安全检查与媒体规范化
        ↓
画面质量 / 人脸区域 / 主体 / 运动轨迹分析
        ↓
确定 Live Photo/视频高光或 GIF 整段、落版帧与首尾闭环方式
        ↓
生成受约束的 MotionPosterPlan
        ↓
主体分割、运动跟踪与三套低清代理渲染
        ↓
用户编辑并冻结 designVersion
        ↓
FFmpeg + 图像渲染器生成所选 MP4/GIF 与 JPG
        ↓
输出内容安全复检与 AI 标识
        ↓
短期私有下载 → iOS App 校验 → 保存到照片资料库/系统分享
```

### 16.1 技术原则

- iOS App 负责系统照片选择、PhotoKit 原始资源读取与配对校验、播放、时间轴交互、低清预览、下载、保存和系统分享。
- 高光分析、主体分割、运动跟踪和高清合成在服务端完成。
- 使用 FFmpeg 等确定性媒体管线完成转码、循环、图层合成，以及 H.264 或 GIF 输出。
- AI 输出结构化计划，不直接生成整段人物视频。
- 不使用生成模型改变人物动作、五官、服饰或身体结构。
- AI 密钥、存储密钥和内容安全凭据只存在服务端。
- 任务采用异步队列、状态机、幂等键、超时、取消和阶段重试。
- 大文件通过后台可恢复的 HTTPS 上传进入私有对象存储并展示真实进度；App 退出前台后按 iOS 后台传输约束继续或恢复。
- 长时间媒体处理使用任务队列和可持续运行的容器/云托管，不依赖一次同步云函数调用。
- 用户退出或 App 进入后台后，服务端任务继续；重新进入后通过 `taskId` 查询恢复。
- 预览和高清使用同一版式、字体、裁切、时间参数和渲染版本。
- 最终文件使用媒体探测工具验证容器、编码、像素格式、帧率、方向、时长和首帧。

### 16.2 媒体规范化

输入后先处理：

- Live Photo 静态照片与 pairedVideo 的资产归属、资源类型、校验和和元数据对应关系。
- EXIF/容器旋转方向。
- 可变帧率转稳定帧率。
- GIF 原文件解帧并统一时间基准，只有一帧时按静态素材拒绝。
- HEVC 等输入转为后端统一代理格式。
- 色彩空间统一为 sRGB/BT.709 兼容输出。
- 生成低清代理与时间轴缩略图。
- 检测损坏帧、黑帧、音轨和异常时长。

原始音轨在 MVP 输出中移除，不发送给非必要服务。

### 16.3 结构化动态海报计划

```text
MotionTask: taskId, ownerId, status, sourceId,
            schemaVersion, designVersion, rendererVersion,
            createdAt, expiresAt

SourceAsset: sourceId, sourceKind, resourceIds,
             importedAt, expiresAt

SourceResource: resourceId, sourceId, role,
                originalFilename, uniformType, checksum,
                byteSize, width, height, duration

CapturePlan: sourceStart, sourceEnd, landingFrame,
             loopType, speed, motionScore,
             subjectTrack, focalTrack, segmentationMaskId

PosterPlan: structureMode, visualStyle, palette, fontPackId,
            dynamicRegion, mediaLayers, textLayers,
            title, subtitle, issueNo, date, randomSeed

RenderAsset: previewVideoId, finalVideoId, finalGifId, coverImageId,
             outputFormats, width, height, duration, fps, codec,
             auditStatus, aiLabelInfo, expiresAt
```

Live Photo 的 `photoLocalIdentifier` 只保存在设备本地用于导入恢复，不作为云端业务标识上传；云端只使用随机 `sourceId` 和各资源 `resourceId`。`mediaLayers` 必须标记静态关键帧、动态层、蒙版层和装饰层类型。旧 `designVersion` 的异步结果不得覆盖用户最新编辑。相同源片段、计划、字体和渲染器版本必须能够稳定复现相同作品。

## 17. 任务状态与失败恢复

```text
草稿 → 上传中 → 输入审核中 → 媒体规范化 → 动态分析中
     → 高光待确认 → 海报规划中 → 低清渲染中 → 待编辑
     → 高清渲染中 → 输出审核中 → 已完成
     → 部分失败 / 已拒绝 / 已取消 / 已过期
```

失败处理：

- Live Photo 资源读取失败：区分权限不足、iCloud 不可用、资源缺失、配对失败和空间不足，允许针对当前阶段重试或重新选择。
- 上传失败：断点或只重试上传阶段。
- 媒体规范化失败：提示具体格式或损坏原因。
- 未找到合格高光：建议手动选择或更换视频。
- 主体跟踪失败：降级为带有非矩形动态区或确定性文字遮罩的安全动态封面，并继续通过四项否决测试。
- 人物分割失败：关闭破版效果，不输出明显毛边。
- 循环失败：切换为交叉过渡、往返循环或要求调整片段。
- AI 文案失败：使用用户原文或无文案版式继续。
- 某个候选失败：其他成功候选仍可使用。
- 高清渲染失败：保留低清方案和所有编辑参数，只重试高清阶段。
- 内容安全未通过：隔离对应源文件或结果，不生成公开地址。
- App 退出或网络中断：通过后台传输记录与 `taskId` 恢复真实阶段，不显示虚假进度。

重复点击、刷新或重试不能重复创建任务、重复扣除额度或覆盖已收藏方案。

## 18. 内容安全、隐私与 AI 标识

- 导入前说明照片访问用途；上传前明确说明 Live Photo 的静态照片与配对视频、普通视频/GIF 将由云端及实际 AI 服务商处理。
- 输入 Live Photo/视频/GIF、用户文字、AI 文案、生成素材和最终 MP4/GIF/JPG 均完成适用的内容安全检查。
- 用户文字和 AI 文案使用适用的文本安全检查。
- 视频输入与输出需要抽取覆盖首尾、镜头变化和动作高光的多帧检查，并接入支持完整视频的安全审核服务。
- 动态素材不能只检查静态首帧；内容安全抽帧必须覆盖首尾、镜头变化和动作高光，必要时使用支持完整视频的审核服务。
- 命中“需复核”的任务进入人工复核或拒绝分享，不能直接生成公开地址。
- 默认使用中国区私有存储和满足业务合规要求的国内服务商。
- Live Photo 原始照片与配对视频、普通视频/GIF、代理视频、主体蒙版和中间文件默认在最后操作后 24 小时内从活动存储删除。
- MP4、GIF 与 JPG 结果默认保留 7 天。用户主动删除时立即撤销访问并使下载地址失效，活动存储及对象版本在 24 小时内清除，加密备份最迟 30 天轮转清除。
- 删除后只保留不含媒体、画面特征和用户文案的最小审计记录，例如任务 ID、删除时间、状态和错误码；保留期限按上线时合规要求确定。
- 用户素材不得用于模型训练，不得建立人物身份库。
- 向 AI 服务发送前移除与生成无关的 GPS、设备和容器元数据。
- MVP 移除原视频音轨，减少语音隐私与循环不连续问题。
- 涉及 AI 文案、生成背景、装饰或其他生成合成内容时，按照上线时有效规则添加显式与隐式 AI 标识。
- 不提供关闭或去除法定 AI 标识的开关。
- 儿童视频、真人肖像、跨境处理和生成式服务备案要求需在上线前专项核验。
- 所有字体、纹理和设计资产必须具有适用于商业输出的授权。

## 19. 非功能要求

### 19.1 性能目标

以一张真实 iPhone Live Photo、一段 1080p、10 秒普通手机视频和一组 720p、多帧、约 6 秒 GIF 作为标准测试素材，网络步骤使用稳定 Wi-Fi：

- 已下载到本机的 Live Photo 两项原始资源读取、配对和本地校验 P90 在 3 秒内完成；iCloud 下载耗时单独统计并展示真实进度。
- 上传和输入审核完成后，高光建议 P90 在 15 秒内出现。
- 3 个低清动态候选 P90 在 60 秒内可预览。
- 1080 × 1350、6 秒高清 MP4 与 JPG 封面 P90 在 90 秒内、P95 在 120 秒内完成；GIF 单独导出的额外编码耗时 P90 不超过 30 秒，选择两种格式时另按实际并行或串行管线验收总时延。
- 预览进入稳定播放后的交互响应不超过 100 ms。
- 最终 MP4 文件目标不超过 15 MB。
- 标准 GIF 文件目标不超过 15 MB，超过时必须在降帧、降尺寸或只保留 MP4 之间让用户选择。
- MVP 支持范围内的主流 iPhone 播放候选、调整时间轴和保存成片时不崩溃、不黑屏。
- 典型任务首次渲染成功率不低于 95%，阶段重试后不低于 99%。
- MP4 在受支持 iOS 真机照片资料库的保存成功率目标不低于 98%。

### 19.2 视觉与动态质量

- 100% 成片通过四项“非视频套框”否决门槛。
- 首帧、落版帧和至少两个中间抽样帧都具有成立的杂志构图。
- 高置信度清晰正脸至少 99% 不被无意裁切或文字遮挡。
- 低置信度分割样本 100% 触发安全降级。
- 最终成片不得改变人物五官或真实动作含义。
- 主标题在至少 80% 播放时长内保持完整可读。
- 同一时刻不得有超过两个争抢注意力的动态区。
- 首尾闭环无黑帧、明显硬跳、严重重影或主体瞬移。
- 3 个候选不能只是更换滤镜、颜色和字体。
- 静态 JPG 封面与 MP4 落版帧的布局、文字和裁切一致。

### 19.3 可靠性与成本

- 上传、规范化、分析、规划、预览、高清、审核均有独立状态与重试。
- 高成本分割或 AI 生成失败时可以降级，不阻断基础动态封面。
- 先生成低清候选，用户确认后才生成高清。
- 重试不得重复扣除额度或重复生成成功资产。
- 生成任务、媒体处理和文件清理均有可审计记录。

## 20. MVP 验收标准

1. 用户可以在 iOS 系统选择器中只选择一张原生 Live Photo，并看到明确的 Live Photo 标识。
2. App 能从同一 `PHAsset` 读取至少一份静态照片资源和一份 `.pairedVideo`，保存资源类型、UTType、原始文件名、尺寸、时长、字节数与校验和，并绑定到同一个 `sourceId`。
3. Live Photo 任一成对资源缺失、损坏或不属于同一资产时必须阻止进入生成；不能只取静态首帧后宣称导入成功。
4. 对仅在 iCloud 的 Live Photo 展示可取消的真实下载进度，支持失败重试；未下载完成、网络断开或本机空间不足时给出准确状态。
5. 用户也可以选择/拍摄一段 3～30 秒视频，或选择一个符合限制的 GIF；GIF 服务端解帧后至少包含 2 帧。
6. 用户未主动选择的照片或视频不会被读取、分析或上传，本地相册原件不会被修改或删除。
7. 系统能够校验 Live Photo 配对关系，以及视频/GIF 的时长、大小、帧数、方向、格式和基础质量，并给出具体错误。
8. AI 为合格 Live Photo/视频推荐可用高光；2～5 秒 GIF 默认使用完整动画，较长 GIF 推荐 1～3 个片段；用户均可预览并调整允许的起止点。
9. Live Photo 静态照片可以作为落版帧候选，用户也可以从动态时间轴更换落版帧和主体焦点。
10. 每次生成 3 个具有结构性差异且与当前素材兼容的动态杂志候选，不强制单次覆盖全部结构模式。
11. MVP 候选池整体至少支持动态封面、主体破版、时间切片 3 种结构模式，并按分割、跟踪和动作轨迹质量决定单个素材可用模式。
12. MVP 至少支持先锋刊头、人文特刊、城市画报 3 种视觉风格系统。
13. 结构模式与视觉风格独立组合；任意两个候选必须模式不同，或在同一模式下同时改变版式层级和时间编排，不能只换滤镜或配色。
14. 100% 候选及安全降级方案通过暂停、结构、时间和候选差异四项否决测试。
15. 落版帧单独导出后仍是一张完整、可读的杂志封面。
16. 动作必须与刊头、文字、版心、前后景或时间切片发生关系。
17. 成片长度为 4～8 秒，默认 6 秒，1 秒内出现主动态。
18. 主标题在至少 80% 时长内保持完整可读。
19. 首尾回到同一落版状态，无黑帧、明显硬跳、严重鬼影或主体瞬移。
20. 同一时刻最多 1 个主动态区和 1 个弱辅助动态区。
21. 高置信度清晰正脸至少 99% 不被无意裁切或遮挡。
22. 人物分割质量不足时 100% 降级，不能输出明显毛边或改变五官。
23. 用户可以调整片段、落版帧、裁切、标题、日期、配色、速度和动态强度。
24. AI 文案不得编造人物关系、地点和经历，所有文字可编辑、关闭或单独重新生成。
25. 低清预览、MP4、GIF 与 JPG 的片段、首尾闭环方式、裁切、层级、字体和换行保持一致。
26. 用户可以选择只导出 MP4、只导出 GIF 或同时导出两种动态格式，并始终获得 JPG 封面；切换输出格式不重新分析素材、不改变版式且不重复扣除生成额度。
27. MP4 为 1080 × 1350、24/30 fps、H.264 High、`yuv420p`、BT.709、`faststart`；标准 GIF 为 720 × 900、12/15 fps、最多 256 色；两者默认静音、方向正确且无黑帧、乱码和异常色彩。
28. 典型 6 秒 MP4 与标准 GIF 均以 15 MB 为目标上限；高清 MP4 不使用低清预览或 GIF 作为渲染源，低分辨率、低码率或高倍放大素材必须显示清晰度警告。
29. 3 个低清候选 P90 在 60 秒内出现，高清 MP4/JPG P90 在 90 秒内、P95 在 120 秒内完成；GIF 单独导出的额外编码耗时 P90 不超过 30 秒，三类输入分别统计。
30. AI 或分割服务不可用时仍可生成受约束的基础动态封面，不退化为视频矩形加边框。
31. Live Photo 读取、iCloud 下载、上传、分析或渲染失败时可以只重试失败阶段，已成功的资源和编辑参数不丢失。
32. 重复点击、断网恢复或旧异步结果不会产生重复任务、重复扣费或覆盖最新编辑。
33. 用户授权后可以把 MP4、GIF 与 JPG 保存到照片资料库或调用系统分享面板；保存后重新读取验证格式和帧数；权限拒绝时不崩溃、不重复弹窗，并可进入系统设置。
34. 结果页明确说明朋友圈视频需要保存后由用户自行发布，GIF 是否保持动画由平台决定，不能承诺自动发布或自动循环。
35. 静态 JPG 封面不会被描述为动态分享；首发版本也不会把 MP4/GIF 错误描述为重新封装后的系统 Live Photo。
36. 输入 Live Photo/视频/GIF、用户文字、AI 文案和最终 MP4/GIF/JPG 均通过适用的内容安全检查。
37. 生成式内容具备上线时要求的显式与隐式 AI 标识。
38. 原素材和中间文件默认 24 小时删除，结果默认 7 天删除；主动删除后访问立即失效，活动媒体 24 小时内清除，备份最迟 30 天清除。
39. 用户甲不能访问用户乙的 Live Photo 成对资源、其他源素材、主体蒙版、计划、预览或结果。
40. 至少使用 20 张来自不同受支持 iPhone 型号的真实 Live Photo，覆盖本地原件、iCloud 原件、横竖屏、HEIC/JPEG、配对 MOV、有限照片权限、拒绝权限、撤销权限和损坏/缺失资源。
41. iOS 真机覆盖“Live Photo→MP4/GIF/JPG、视频→MP4/GIF/JPG、GIF→MP4/GIF/JPG”三条主路径；从测试账号手动发布 MP4/GIF 到测试朋友圈，回看记录压缩、裁切、封面、文字、方向、播放和重播表现。
42. 使用至少 20 组不同动作样片盲测，至少 80% 用户第一描述包含“杂志、封面或动态海报”。
43. 盲测中描述为“视频套模板、加边框”的比例不超过 20%。
44. 至少 80% 用户能在 5 秒内指出作品的视觉主角。

## 21. 暂不进入 MVP

- 将编辑结果重新封装并写回为系统原生 Live Photo；首发先输出 MP4、GIF 与 JPG。
- Android App，以及各厂商 Motion Photo 的专项读取。
- 微信小程序内原生读取 Live Photo；标准小程序接口不能获得完整成对资源。
- 多段视频、多轨时间线和超过一个主要视频素材。
- 9:16、1:1、横版等多比例同时首发。
- 保留原声、音乐、节拍卡点和配音。
- 无限自由提示词。
- 生成或改变人物动作、面容、服饰和身体结构。
- 复杂关键帧、任意图层、贴纸商城和专业视频编辑能力。
- 静默或自动替用户发布朋友圈。
- 公开作品社区、多人协作和复杂会员系统。

## 22. 请用户重点审核的产品决定

| 审核项 | 当前建议 |
| --- | --- |
| 核心产品 | 单个动态杂志封面，不再默认生成三页静态杂志 |
| 首发平台 | Swift/SwiftUI 原生 iOS App＋云端渲染；微信小程序后续只做作品入口 |
| MVP 输入 | 原生 iOS Live Photo 为主入口，同时支持 1 段 3～30 秒视频或 1 个受限制 GIF |
| Live Photo | PhotoKit 读取同一 PHAsset 的原始照片与 pairedVideo，进入首发 P0 |
| Live Photo 输出 | 首发输出 MP4/GIF/JPG；重新封装为系统 Live Photo 后续单独验收 |
| 高光流程 | Live Photo/视频推荐高光并默认选中最佳；短 GIF 默认整段，长 GIF 推荐 1～3 个 |
| 动态候选 | 每次生成 3 个与素材兼容、具有结构性差异的方案 |
| 输出比例 | 4:5 竖版 |
| 输出文件 | 用户选择 MP4、GIF 或两者；始终附 JPG 封面，默认推荐高清 MP4 |
| 首发结构 | 动态封面、主体破版、时间切片 |
| 首发视觉 | 先锋刊头、人文特刊、城市画报 |
| 人物处理 | 只编辑真实动态，不生成或修改人物面容与动作 |
| 音频 | MVP 默认移除，第二阶段再考虑原声和音乐 |
| 朋友圈发布 | MP4 保存后由用户自行发布；GIF 是否保留动画及自动播放、重播、封面和压缩均由平台决定 |
| 原素材期限 | 默认 24 小时；主动删除后访问立即失效，活动文件 24 小时内清除 |
| 结果期限 | 默认 7 天；主动删除后访问立即失效，备份最迟 30 天清除 |
| AI 标识 | 按法规和平台要求保留，不提供关闭开关 |
| 商业模式 | MVP 暂不收费，先验证动态海报质量与分享完成率 |
