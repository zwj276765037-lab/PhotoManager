# PhotoManager 本地人生杂志网站需求

> 版本：v0.9-draft
>
> 状态：已确认本地网站作为首发验证形态，iOS App 作为后续预案
>
> 更新时间：2026-08-29
>
> 本轮主题：明确动态输入与静态输入，并让 iPhone 能把结果存入“照片”

## 1. 用户初衷与产品定位

目前常见照片应用要么只做静态拼图，要么把 Live Photo 降级成静态照片或普通视频，再增加边框、滤镜和贴纸，缺少一种能保留真实动态并把它编辑成“会动的杂志封面”的产品。

本项目当前先做成本地网站，用于验证核心体验和渲染质量。网站运行在用户电脑上，iPhone 与电脑连接同一可信 Wi-Fi 后，可通过 Safari 打开局域网地址，上传普通照片、视频、GIF，或先把 Live Photo 在系统照片中“存储为视频”后上传。普通照片生成静态 JPG 杂志封面，视频和 GIF 生成动态版本；网站在电脑本地完成任务管理和渲染，不把素材发送到云端。

Safari 网页没有 PhotoKit 权限，不能可靠取得原生 Live Photo 的“静态原图＋配对 MOV”。如果浏览器只返回 HEIC/JPG 静态文件，网站应立即预览并允许用户生成静态 JPG 杂志封面，同时明确提示该结果不含 Live Photo 动作；要保留真实动态，用户仍需先“存储为视频”。原生资源成对读取保留为后续 iOS App 预案。

一句话主张：

> 不是给动态素材套模板，而是把这一刻编成会动的杂志封面。

“一张图”在这里描述的是视觉体验：它看起来是一张完整的竖版杂志封面，用户可以选择经过首尾闭环设计的短 MP4、GIF 动态图片或两者，同时附带一张静态 JPG 封面。文件本身不能强制社交平台重复播放，只有在支持循环的播放器中才会连续循环。

## 2. 产品不是什么

- 不是把多个视频平均放入方格。
- 不是在普通视频外面增加纸张边框。
- 不是让原视频从头到尾在矩形窗口里播放。
- 不是依靠滤镜、贴纸、慢推和淡入淡出伪装成“AI 风格”。
- 不是生成模型重新绘制人物动作或面容。
- 不是复杂的多轨视频剪辑软件。

AI 的核心角色是“动态主编”：选择高光片段、确定落版帧、理解主体运动、设计主体与文字/版心的关系，并让动作最终回到一张可阅读的杂志封面。

## 3. 核心术语

| 名称 | 定义 |
| --- | --- |
| 原生 Live Photo | iOS 照片资料库中的动态照片资产；网页不能直接获得其 PhotoKit 成对原始资源 |
| Live Photo 网页桥接 | 用户在 iPhone 照片 App 选择“存储为视频”，再把保留真实动作的新视频上传到本地网站 |
| 静态照片模式 | 浏览器把可解码的照片在本机规范化为高质量 JPEG，电脑只生成 JPG 杂志封面，不宣称含有动态 |
| 动态源 | 用户主动选择的一段短视频或一个 GIF；每个任务只处理一个动态源 |
| 高光片段 | AI 推荐的、适合被编辑成循环海报的 2～5 秒动作片段 |
| 落版帧 | 动态开始与结束时呈现的完整杂志封面画面，也是静态封面来源 |
| 动态主视觉 | 页面中承担主要动作和第一视觉中心的区域 |
| 动态杂志海报 | 视觉上是一张杂志海报、实际以首尾可无缝衔接的 MP4 或 GIF 交付的最终作品 |
| 结构模式 | 动态封面、主体破版、时间切片等空间和时间组织方式 |
| 视觉风格 | 字体、色彩、刊头、线条、文案语气和材质组成的设计系统 |

## 4. MVP 输入与输出

### 4.1 输入

MVP 每次处理一个素材：一张普通照片、一段短视频或一个 GIF。照片进入静态 JPG 流程；Live Photo 要保留动作时使用系统“存储为视频”桥接，生成的视频进入普通视频流程。

手机与 Live Photo 要求（首发 P0）：

- 本地服务默认监听局域网地址，同时显示电脑本机地址和手机访问地址。
- iPhone 与运行网站的电脑连接同一可信 Wi-Fi 后，可以在 Safari 完成选择、上传、选项设置、状态查看、结果预览和保存。
- 网站文件选择器允许用户尝试选择 Live Photo；若 Safari 只返回 HEIC、JPG 或其他静态图，前端立即预览并准备静态 JPG 任务，同时显示“照片 App → … → 存储为视频”的动态保留步骤。
- 转换后的视频必须包含真实动态且可以在提交前预览；网站不能把静态图、损坏视频或只有一帧的文件描述为动态照片。
- 首发不读取原生 `PHAsset`、静态原图或 `.pairedVideo`，也不宣称保留 Live Photo 的原始配对元数据。
- 局域网原型没有账号和访问密码，只允许在可信网络临时启动；不得做路由器端口映射或暴露到公网，用完后由用户停止本地服务。

静态照片要求：

- 支持浏览器可解码的 HEIC/HEIF、JPG、PNG、WebP 等照片；前端统一转换为高质量 JPEG 后上传，最长边最多 4096 像素，避免手机内存失控。
- 选择后先显示照片、文件名、原格式、大小与准备状态；转换完成后主按钮改为“生成静态杂志封面”。
- 静态任务只输出 JPG，不开放 MP4/GIF 与视频清晰度选项；服务端也必须强制静态输入使用 JPG 输出，不能只依赖前端。
- 浏览器不能解码某种照片时显示明确错误与占位预览，建议先导出为 JPG；不得出现点击后无反馈。
- 静态照片可以使用三种杂志结构或同时生成三版，但不能被标记为 Live Photo 或动态封面。

短视频要求：

- 来源：手机相册选择或直接拍摄。
- 原视频时长：3～30 秒。
- MVP 硬上限：100 MB；超过后先提示用户裁短或在系统中压缩，不直接上传。上限可根据真机和后端压力测试下调。
- 支持方向：横屏或竖屏，后端统一处理方向和色彩空间。
- 直接拍摄普通视频时由原生相机入口限制最长 30 秒；从照片资料库选择后仍需重新读取媒体信息并校验时长。

GIF 要求：

- 从相册作为图片选择后上传原文件。
- 时长建议 2～10 秒、文件不超过 50 MB、总帧数不超过 300 帧。
- 服务端根据文件头和实际帧数识别，不能只依赖扩展名。
- 选择后不能先经过 Canvas、图片压缩或重新编码，避免只保留静态首帧。
- 若 iOS 照片资料库或文件选择器只返回静态版本，必须提示用户改用视频，不能宣称已经获得动画。
- 2～5 秒 GIF 默认使用完整动画，只需确认落版帧和首尾闭环方式，不强制挑选 3 个高光。
- 超过 5 秒的 GIF 进入同一动态源时间轴，由系统推荐 1～3 个动作完整的片段，用户也可保留整段或手动调整。

三类输入都可以附带可选主题、一句话、日期和视觉风格，全部可以跳过。

普通照片、视频与 GIF 是本地网站的直接输入。原生 iOS Live Photo 与 Android 各厂商 Motion Photo 的成对资源读取不进入网页首发版本。

### 4.2 输出

本地网站允许用户先选择一个结构快速生成，也可以选择“同时生成三版”进行比较。用户可以导出“视频 MP4”“动态图片 GIF”或同时导出两种格式；切换输出格式不需要重新分析素材或改变版式。

静态照片输入固定输出一张或多张 1080 × 1350 JPG 杂志封面；选择“同时生成三版”时另附三版静态对比图。静态模式不生成伪动态 MP4/GIF。

共同规格：

- 成片比例：4:5 竖版。
- 成片时长：4～8 秒，默认 6 秒。
- 两种动态格式使用相同片段、落版帧、首尾闭环、版式和文字。
- 始终附带 1 张 1080 × 1350 JPG 静态封面。

MP4 视频输出：

- 尺寸：1080 × 1350。
- 帧率：24 或 30 fps，由渲染器统一，不沿用异常可变帧率。
- 视频编码：H.264 High、`yuv420p`、BT.709，写入 `faststart`。
- 音频：MVP 默认静音，不复制原视频语音。
- 默认使用“高清优先（high）”编码；另提供“节省空间（standard）”档。
- 文件大小目标：15 MB 以内，最终按画面复杂度动态控制码率。

GIF 动态图片输出：

- 标准尺寸：720 × 900；高清 GIF 是否开放取决于体积和真机测试。
- 帧率：12 或 15 fps。
- 最多 256 色，不宣称与 MP4 等画质。
- 文件大小目标：15 MB 以内；超限时先降低帧率或尺寸并让用户确认。
- 默认静音；GIF 格式本身不支持音频。

是否自动播放、重复播放以及使用哪一帧作为平台封面，由朋友圈或其他社交平台决定，产品不能承诺。

### 4.3 输出格式与清晰度原则

- 用户可以按用途选择 GIF 或 MP4，输入格式不限制输出格式。
- MP4 是“清晰优先”推荐项，适合人物、渐变、夜景、文字和朋友圈视频发布。
- GIF 是“动态图片兼容”选项，但只有 256 色，同等观感下通常体积更大，平台也可能压缩或只显示首帧。
- 视频输入生成 MP4 时必须从原始视频或高质量规范化输入直接渲染，不能先转 GIF 再转回视频。
- GIF 输入必须先完整解帧，再生成高质量内部时间轴；最终可分别编码为 MP4 或 GIF。
- 不进行无意义的多次转码；预览代理不得作为高清输出源。
- MP4、GIF 与 JPG 应从同一个无损或等效高质量版式母版分别编码，GIF 不得先经过有损 MP4 再导出。
- 输入规范化必须按原始宽高比、方向和主体焦点计算裁切，并只做一次高质量缩放；高分辨率源不得先固定降到 720 像素再放大输出。
- 720 像素宽的源画面放大到 1080 像素只改变输出尺寸，不会产生真实新细节。系统必须在低分辨率、低码率、夜景运动模糊或放大比例过高时提示“清晰度受原素材限制”。
- “高清优先”使用高质量缩放和较低压缩强度，减少二次损失；锐化只能适度使用，不能把光晕、噪声或伪细节冒充清晰度。

因此，默认推荐 MP4，但 GIF 输出正式进入 MVP，并由用户在结果页选择。

## 5. 首发平台与分享边界

### 5.1 本地网站是首发验证端

- 首发采用原生 HTML/CSS/JavaScript 工作台与 Python 本地服务，复用 FFmpeg 确定性渲染器。
- 服务默认只用于同一局域网内的电脑和手机，不依赖云端账号、对象存储或 AI 服务。
- 电脑负责保存临时素材、串行执行高负载渲染、记录任务状态并提供结果下载；手机只承担浏览器交互，不在手机端执行高清 FFmpeg。
- 单文件硬上限 100 MB；上传、任务信息、日志和结果保存在 Git 忽略的本地运行目录。
- 网站必须支持移动端触控、窄屏布局、Safari 媒体预览和大尺寸操作按钮。
- iOS App 与微信小程序均为后续预案，不是当前本地网站验收的阻塞项。

### 5.2 保存和分享

- 每个结果同时提供“打开并保存”和“下载到‘文件’”两个入口，不能再使用含义不清的“保存到本机”。
- iPhone 用户点“打开并保存”后：MP4 使用 Safari 分享菜单“存储视频”；GIF 使用长按或分享菜单“存储图像”；JPG 使用长按“存储到照片”。页面必须按格式显示这一步骤。
- “下载到‘文件’”只承诺把原文件交给 Safari 下载管理和“文件”App，不宣称自动进入系统照片资料库。
- 电脑浏览器直接下载到本机；输出链接支持视频 Range 请求和拖动预览。
- 朋友圈稳定主路径仍是“保存 MP4 到系统相册 → 用户打开朋友圈并选择视频发布”。
- App 不承诺静默、自动或一键替用户发布朋友圈，也不把分享面板成功弹出等同于发布成功。
- GIF 保存到系统相册后必须重新读取并验证是否仍含多帧；若目标平台降级为静态图，明确推荐 MP4。
- JPG 是静态封面，不被描述为动态输出。
- 朋友圈中的自动播放、重复播放、封面选择、压缩和裁切均由微信客户端决定；项目只保证导出文件自身首尾可无缝衔接，并通过真实发布测试记录平台表现。

其他社交平台默认以“保存 MP4 后由用户上传”为通用路径；GIF 是否保持动画需按目标平台真机验证。

## 6. 结构模式与视觉风格必须分开

结构模式决定“画面怎样动”，视觉风格决定“杂志长什么样”。如果两者混在一起，3 个候选很容易退化为同一模板换颜色。

MVP 建议构成一个 3 × 3 的受控组合空间：3 种结构模式 × 3 种视觉风格。AI 先排除不适合当前素材的结构，再挑选 3 个结构性差异最大的候选，不需要把 9 种组合全部展示给用户，也不强制一次覆盖全部 3 种结构。

## 7. 三种首发结构模式

### 7.1 动态封面

- 视频或关键帧占据主要版面，可以满版或使用非矩形遮罩。
- 刊头、大标题和栏目文字与主体形成前后层次。
- 动作展开时，主体可以经过刊头、穿过文字留白或跨越版心。
- 首尾回到完整落版封面，暂停时依然像一本杂志。

适合：人物转身、回头、行走、挥手、宠物动作、风景变化。

### 7.2 主体破版

- 先以落版帧建立静态杂志构图。
- 将人物、宠物、车辆或其他运动主体分割出来。
- 动态主体可以越出版心、压住刊头、穿过色块或在前后景之间运动。
- AI 只保留真实像素和真实动作，不补画或重绘人物。
- 分割质量不足时自动降级为安全整图动态封面。

适合：人物动作明确、背景相对稳定、主体轮廓清晰的视频。

### 7.3 时间切片

- 从同一动作中提取 2～4 个关键时间相位。
- 使用不等宽切片、延迟回声、局部定格或动作轨迹表现时间经过。
- 页面只有一个主动态，其余相位是静态、弱动态或延迟回声。
- 禁止把切片做成等宽方格或普通胶片九宫格。

适合：跳跃、舞动、奔跑、转身、抛物、运动和有明确动作轨迹的片段。

### 7.4 结构适用门槛

- 主体破版只有在主体分割、边缘质量和运动跟踪均达标时才能进入候选池。
- 时间切片只有在动作轨迹清晰、各时间相位可辨且不会产生错误肢体关系时才能进入候选池。
- 风景变化、镜头移动或主体不明确的素材优先使用动态封面。
- 同一素材可以产生多个动态封面候选，但动态区域、前后层级和时间编排必须形成结构性差异。
- 安全降级方案仍必须通过“非视频套框”四项否决门槛，不能变成全屏视频叠标题。

## 8. 三种首发视觉风格

### 8.1 先锋刊头

- 黑、白、信号红或高对比配色。
- 粗无衬线刊头、超大标题、克制的小字栏目。
- 适合人像、动作、时尚和强视觉内容。

### 8.2 人文特刊

- 暖中性色、米白、墨黑和低饱和照片。
- 宋体与无衬线组合，纪实注释和短引文。
- 适合家人、生活、宠物和自然动作。

### 8.3 城市画报

- 冷灰、钴蓝或建筑色彩。
- 窄体字、竖向栏目眉、建筑式切割和细线。
- 适合街拍、旅行、夜景、展览和城市运动。

每套视觉风格需要定义字体授权、字重、颜色、刊头、栏目、文字语气、版心、安全区和装饰规则，而不仅是一个滤镜。

## 9. 完整用户流程

```text
电脑启动本地网站，手机连接同一可信 Wi-Fi 并打开局域网地址
        ↓
选择一段 3～30 秒视频或一个 2～10 秒 GIF
        ↓
若素材是 Live Photo，先在 iPhone 照片 App 中“存储为视频”
        ↓
上传到运行网站的电脑并完成本地格式、大小与动态检查
        ↓
AI 分析清晰度、镜头稳定性、主体、人脸与运动轨迹
        ↓
视频推荐高光；短 GIF 默认使用整段，长 GIF 推荐 1～3 个片段
        ↓
用户确认默认片段，或展开时间轴调整起止点与落版帧
        ↓
填写可选主题、一句话、日期和视觉风格
        ↓
AI 生成文案、结构模式、空间版式与时间编排
        ↓
按用户选择生成一个结构，或同时生成 3 个结构性差异候选
        ↓
用户选择并进行轻量编辑
        ↓
用户选择 MP4、GIF 或两者，并生成 JPG 封面
        ↓
输出内容安全复检与适用的 AI 标识
        ↓
手机或电脑下载结果 / 使用系统分享菜单保存或发布
        ↓
用户发布到朋友圈或其他社交平台
```

## 10. AI 动态捕捉

### 10.1 动态源质量分析

AI 分析：

- 视频方向、分辨率、帧率、码率和时长。
- 模糊、过曝、欠曝、黑帧和镜头剧烈抖动。
- 人脸与主要物体位置。
- 主体运动幅度、方向、速度和轨迹。
- 可用于刊头与标题的低信息区域。
- 首尾画面是否适合形成自然循环。

AI 不保存人物身份特征，不根据外表推断身份、关系、职业或其他敏感信息。

### 10.2 高光片段与整段使用策略

对于 Live Photo 和普通视频，系统推荐最多 3 个高光片段，每个片段长度 2～5 秒；不足 3 个合格片段时不强行补齐。系统默认选中评分最高的一个，其他建议折叠为“换一个瞬间”，避免让用户连续做两轮复杂选择。

对于 GIF：

- 2～5 秒时默认使用完整动画，用户直接确认落版帧和首尾闭环方式。
- 超过 5 秒时推荐 1～3 个动作完整的片段，也允许用户保留整段。
- GIF 解帧后与视频使用同一动态源时间轴、质量评分、落版帧和渲染流程。

高光评分不能只看运动幅度，还应综合：

- 主体清晰度。
- 动作完整度。
- 构图安全区。
- 镜头稳定性。
- 人脸与关键动作可见性。
- 首尾循环可行性。
- 与用户主题的非敏感视觉匹配度。

用户可以接受默认选择、展开其他推荐，也可以在时间轴上手动微调起止点。若没有合格片段，系统需要明确建议更换素材或手动选择，不能硬套低质量模板。

### 10.3 落版帧

AI 为每个片段推荐一个落版帧：

- 暂停时主体清晰、表情和动作完整。
- 有足够区域放置刊头与标题。
- 能作为循环的开始与结束状态。
- 单独导出为 JPG 时仍是一张成立的杂志封面。

用户可以拖动时间轴更换落版帧。

### 10.4 循环方式

根据素材选择：

- 自然闭环：原动作首尾位置接近，直接对齐循环。
- 交叉过渡：短时间混合首尾，隐藏轻微差异。
- 往返循环：动作正向后平滑反向，适用于部分非周期动作。
- 落版回收：动作结束后通过遮罩或版式变化回到落版状态。

不能为了循环产生明显鬼影、倒放违和、黑帧或主体瞬移。用户可以预览循环后再确认。

## 11. 六秒标准时序示例

```text
0.0–0.6 秒  完整落版封面，刊头和标题可阅读
0.6–3.2 秒  主体从静态层中运动，与刊头/版心发生层次关系
3.2–4.8 秒  动作高潮，以一次时间切片或局部强调呈现
4.8–6.0 秒  动作回落并恢复到与首帧一致的落版状态
```

不同模板可以改变节奏，但都必须包含“可阅读的落版 → 动态展开 → 回到落版”的闭环。

## 12. 杂志空间版式硬规则

1. 暂停在首帧或落版帧时，必须独立成立为一张杂志海报。
2. 每个作品只有一个第一视觉中心。
3. 禁止 2×2、3×3、等宽分栏和居中视频矩形加边框。
4. 动态主视觉建议占页面 55%～85%，明显大于辅助定格画面。
5. 必须包含刊头、主标题，以及栏目/日期/图注中的至少一种辅助信息。
6. 最多使用 2 套字体、3 个字重和 4 级字号。
7. 至少使用一种深度编辑关系：主体压字、字压主体、破版、前后景遮挡、时间切片或非矩形动态遮罩。
8. 单纯滤镜、缩放、纸张边框、贴纸和淡入淡出不算深度编辑关系。
9. 画面必须保留可读的负空间或低信息区域。
10. 人脸、眼睛和关键动作不得被文字或裁切无意遮挡。
11. 关键主体与标题尽量位于中部 1:1 安全区域，兼顾社交平台缩略图裁切。
12. 装饰不能比真实动作更抢眼，也不能生成未经授权的品牌 Logo。
13. 标题建议 4～12 字，副标题 10～24 字，图注可关闭。
14. 不根据人物外表编造关系、地点、经历或情绪事实。

## 13. 动态时间编排硬规则

1. 成片 4～8 秒，开头与结尾回到同一落版状态。
2. 1 秒内必须出现主要动态，不能长时间只显示静态封面。
3. 同一时间最多 1 个主动态区和 1 个弱辅助动态区。
4. 主标题和刊头在大部分播放时长内保持可读。
5. 文字动画只使用克制的遮罩、错位或轻微位移，禁止频繁跳动。
6. 动作必须与版式发生关系，不能只在固定矩形内播放。
7. 不能只靠全画面慢推、淡入淡出、滤镜或转场制造动态感。
8. 避免频闪、快速抖动和过多转场，优先保留真实动作节奏。
9. 首尾不能出现黑帧、硬跳、明显重影或主体瞬移。
10. 分割、跟踪或循环置信度不足时使用安全降级或要求重选。
11. 静态封面、首帧和结束帧必须使用相同落版设计。
12. MVP 默认静音，避免原声隐私、循环断点和社交平台自动播放差异。

## 14. 防止退化为“视频套框”的四项否决门槛

每个候选和最终作品都必须通过：

1. 暂停测试：隐藏播放控件，落版帧仍被认为是一张杂志封面。
2. 结构测试：至少有一种主体、文字与版心的深度关系；只有外框、贴纸或滤镜直接淘汰。
3. 时间测试：运动具有“落版 → 展开 → 回落”的编排，不是原视频从头播到尾。
4. 候选差异测试：任意两个候选必须使用不同的兼容结构模式，或在使用同一模式时同时改变版式层级与时间编排；不能只换颜色、字体或滤镜。

任一门槛不通过时，方案不能进入用户候选列表。

## 15. 页面与功能需求

### 15.1 首页

- 主入口：“捕捉一个会动的封面”。
- 示例自动静音循环，首帧显示完整杂志封面。
- 示例明确区分动态封面、主体破版和时间切片。
- 提供最近草稿和最近作品。
- 首次使用说明素材只上传到当前电脑的本地服务，不会发送到云端，并提醒仅在可信局域网开启。

### 15.2 动态源选择与检查

- 从手机或电脑浏览器选择一张照片、一段视频或一个 GIF；手机也可从系统照片选择器进入。
- 选择静态照片后，页面必须立即显示照片、文件名、格式、大小和本机准备状态；准备成功后可提交生成静态 JPG，不能表现为点击后没有反应。
- 用户选择 Live Photo 后若 Safari 只返回静态 HEIC/JPG，页面可以按普通照片生成静态封面，但必须同时显示“存储为视频”步骤，并明确静态结果不含动作。
- 显示输入类型、时长、大小、方向、帧数、清晰度和格式检查。
- 视频超过 30 秒时提示先裁剪，不能直接进入生成。
- GIF 超过时长、大小或帧数限制时提示转换为视频。
- 其他不支持、损坏或只有一帧的素材明确说明原因。
- 不读取用户未选择的其他视频或照片。

### 15.3 动态源时间轴

- 显示普通视频或 GIF 解帧后的统一时间轴。
- 视频显示最多 3 个高光建议；2～5 秒 GIF 默认选中完整动画；较长 GIF 显示 1～3 个建议。
- 默认方案直接首尾衔接预览，其他高光折叠为“换一个瞬间”。
- 用户可以拖动起止点、选择落版帧和调整主体焦点。
- 片段过短、过长或无法循环时实时提示。
- 用户确认片段后再进入风格生成，减少无效推理。

### 15.4 本期信息与风格

可选字段：

- 主题。
- 一句话。
- 日期。
- 结构偏好，或交给“AI 动态主编”。
- 视觉风格，或智能推荐。

所有 AI 文案都可编辑、隐藏或单独重新生成。用户不提供信息时，只能生成中性文案，不编造具体事件。

### 15.5 单版生成与三版候选

- 用户可以先选择一个结构快速生成，也可以同时生成三个候选进行比较。
- 三个候选使用低清代理视频首尾衔接预览。
- 每个候选显示结构模式、视觉风格、片段和文件生成预估。
- 任意两个候选使用不同的兼容结构模式，或在同一模式下同时改变主体/文字层级和时间编排。
- 用户可以收藏候选、换一批、锁定片段后重排或进入编辑。
- 换一批不得覆盖已收藏候选和用户文字。

### 15.6 轻量编辑器

用户可以：

- 在当前视频可用的高光建议之间切换，使用短 GIF 完整动画，或微调起止点。
- 更换落版帧。
- 调整主体焦点与安全裁切。
- 编辑或关闭刊头、标题、日期和图注。
- 在当前结构内切换 2～3 个安全版式变体。
- 更换字体组合和配色。
- 选择慢、标准、快三档动作速度。
- 调整低、中、高三档动态强度。
- 锁定已确认片段后只重新生成文案或版式。
- 撤销最近一步并恢复 AI 初始方案。

MVP 不提供任意元素拖动、复杂关键帧、多轨时间线、贴纸商城和音乐编辑器。

### 15.7 结果页

- 在 App 播放器中连续预览高清成片的首尾衔接效果。
- 选择“视频 MP4”“动态图片 GIF”或“两种都要”，切换格式不重新生成版式。
- 保存 MP4 到系统相册。
- 下载或保存 GIF；若真机验证发现系统只保留首帧，则明确提示改用 MP4。
- 保存 JPG 静态封面。
- 使用系统分享面板分享 MP4/GIF/JPG；若用户安装微信，可由用户选择其支持的目标入口。
- 显示每种格式的尺寸、帧率、预计体积、清晰度说明和平台兼容性提示。
- 继续编辑或只重试失败的高清渲染。
- 删除当前电脑上的本地任务副本、中间文件和结果；不删除手机或电脑中的原素材。
- 清楚提示“朋友圈请先保存视频，再从朋友圈选择发布”。

## 16. 技术工作方式

```text
电脑启动本地 Python 服务，手机通过同一 Wi-Fi 访问
        ↓
浏览器选择普通视频/GIF；Live Photo 先由系统存储为视频
        ↓
局域网上传到电脑的任务专属本地目录
        ↓
输入内容安全检查与媒体规范化
        ↓
画面质量 / 人脸区域 / 主体 / 运动轨迹分析
        ↓
确定视频高光或 GIF 整段、落版帧与首尾闭环方式
        ↓
生成受约束的 MotionPosterPlan
        ↓
主体分割、运动跟踪与三套低清代理渲染
        ↓
用户编辑并冻结 designVersion
        ↓
FFmpeg + 图像渲染器生成所选 MP4/GIF 与 JPG
        ↓
输出内容安全复检与 AI 标识
        ↓
本地 HTTP Range 预览与下载 → 手机/电脑保存或系统分享
```

### 16.1 技术原则

- 浏览器负责选择、移动端交互、上传、状态轮询、预览和下载；Python 本地服务负责任务、文件隔离和串行调度。
- 高光分析、主体分割、运动跟踪和高清合成在运行网站的电脑上完成；首版不调用云端服务。
- 使用 FFmpeg 等确定性媒体管线完成转码、循环、图层合成，以及 H.264 或 GIF 输出。
- AI 输出结构化计划，不直接生成整段人物视频。
- 不使用生成模型改变人物动作、五官、服饰或身体结构。
- 首版本地网站不需要 AI 密钥、云存储密钥或账号凭据。
- 任务采用异步队列、状态机、幂等键、超时、取消和阶段重试。
- 素材通过局域网 HTTP 上传到任务专属目录；首版限制 100 MB，并明确显示这是可信内网原型而非公网服务。
- 长时间媒体处理使用电脑上的单工作线程异步队列，不阻塞浏览器请求。
- 手机锁屏、Safari 进入后台或页面刷新后，电脑任务继续；重新打开页面后通过 `taskId` 查询恢复。
- 预览和高清使用同一版式、字体、裁切、时间参数和渲染版本。
- 最终文件使用媒体探测工具验证容器、编码、像素格式、帧率、方向、时长和首帧。

### 16.2 媒体规范化

输入后先处理：

- EXIF/容器旋转方向。
- 可变帧率转稳定帧率。
- GIF 原文件解帧并统一时间基准，只有一帧时按静态素材拒绝。
- HEVC 等输入转为后端统一代理格式。
- 色彩空间统一为 sRGB/BT.709 兼容输出。
- 生成低清代理与时间轴缩略图。
- 检测损坏帧、黑帧、音轨和异常时长。

原始音轨在 MVP 输出中移除，不发送给非必要服务。

### 16.3 结构化动态海报计划

```text
MotionTask: taskId, ownerId, status, sourceId,
            schemaVersion, designVersion, rendererVersion,
            createdAt, expiresAt

SourceAsset: sourceId, sourceKind, originalFilename,
             uniformType, checksum, byteSize,
             width, height, duration, importedAt

CapturePlan: sourceStart, sourceEnd, landingFrame,
             loopType, speed, motionScore,
             subjectTrack, focalTrack, segmentationMaskId

PosterPlan: structureMode, visualStyle, palette, fontPackId,
            dynamicRegion, mediaLayers, textLayers,
            title, subtitle, issueNo, date, randomSeed

RenderAsset: previewVideoId, finalVideoId, finalGifId, coverImageId,
             outputFormats, width, height, duration, fps, codec,
             auditStatus, aiLabelInfo, expiresAt
```

`sourceId` 使用随机任务标识，原始文件名不作为磁盘路径。`mediaLayers` 必须标记静态关键帧、动态层、蒙版层和装饰层类型。旧 `designVersion` 的异步结果不得覆盖用户最新编辑。相同源片段、计划、字体和渲染器版本必须能够稳定复现相同作品。

## 17. 任务状态与失败恢复

```text
草稿 → 上传中 → 输入审核中 → 媒体规范化 → 动态分析中
     → 高光待确认 → 海报规划中 → 低清渲染中 → 待编辑
     → 高清渲染中 → 输出审核中 → 已完成
     → 部分失败 / 已拒绝 / 已取消 / 已过期
```

失败处理：

- Safari 只返回 Live Photo 静态图：允许生成静态 JPG，同时显示“存储为视频”步骤；不能标记为动态导入成功。
- 浏览器无法解码照片：保留文件信息和占位预览，禁用生成并建议先导出为 JPG 或视频。
- 上传失败：断点或只重试上传阶段。
- 媒体规范化失败：提示具体格式或损坏原因。
- 未找到合格高光：建议手动选择或更换视频。
- 主体跟踪失败：降级为带有非矩形动态区或确定性文字遮罩的安全动态封面，并继续通过四项否决测试。
- 人物分割失败：关闭破版效果，不输出明显毛边。
- 循环失败：切换为交叉过渡、往返循环或要求调整片段。
- AI 文案失败：使用用户原文或无文案版式继续。
- 某个候选失败：其他成功候选仍可使用。
- 高清渲染失败：保留低清方案和所有编辑参数，只重试高清阶段。
- 内容安全未通过：隔离对应源文件或结果，不生成公开地址。
- 手机锁屏、页面退出或局域网中断：电脑任务继续，通过 `taskId` 恢复真实阶段，不显示虚假进度。

重复点击、刷新或重试不能重复创建任务、重复扣除额度或覆盖已收藏方案。

## 18. 内容安全、隐私与 AI 标识

- 上传前明确说明视频/GIF 只传到当前电脑，本地原型不使用云端或第三方 AI 服务。
- 输入视频/GIF、用户文字、生成素材和最终 MP4/GIF/JPG 均完成适用的本地格式与安全边界检查；未来公开上线时再接入合规内容安全服务。
- 本地原型不生成公开地址、不提供作品社区，也不把个人素材交给第三方内容安全服务。
- 动态素材的格式与完整性检查不能只检查静态首帧，至少覆盖实际解码、首尾和异常帧。
- 未来接入云端或公开分享前，再为用户文字、动态输入和输出接入适用的多帧/完整视频内容安全服务。
- 普通视频/GIF、代理视频、主体蒙版和中间文件保存在本地 Git 忽略目录；首版由用户停止服务后手动清理，正式产品再实现自动期限清理。
- MP4、GIF 与 JPG 结果当前保留在本地任务目录，用户可在导出后清理；自动清理和删除入口进入下一轮本地功能。
- 用户素材不得用于模型训练，不得建立人物身份库。
- 本地原型不向 AI 服务发送素材；未来接入前需移除与生成无关的 GPS、设备和容器元数据。
- MVP 移除原视频音轨，减少语音隐私与循环不连续问题。
- 涉及 AI 文案、生成背景、装饰或其他生成合成内容时，按照上线时有效规则添加显式与隐式 AI 标识。
- 不提供关闭或去除法定 AI 标识的开关。
- 儿童视频、真人肖像、跨境处理和生成式服务备案要求需在上线前专项核验。
- 所有字体、纹理和设计资产必须具有适用于商业输出的授权。

## 19. 非功能要求

### 19.1 性能目标

以一段由真实 iPhone Live Photo“存储为视频”得到的素材、一段 1080p、10 秒普通手机视频和一组 720p、多帧、约 6 秒 GIF 作为标准测试素材，手机与电脑连接稳定 Wi-Fi：

- 手机打开首页和读取任务历史 P90 在 2 秒内完成；局域网上传显示真实状态，耗时按文件大小与网络单独记录。
- 本地输入检查完成后，高光建议 P90 在 15 秒内出现。
- 单个低清动态候选 P90 在 60 秒内可预览；同时生成三版的总耗时单独统计，P90 目标不超过 180 秒。
- 1080 × 1350、6 秒高清 MP4 与 JPG 封面 P90 在 90 秒内、P95 在 120 秒内完成；GIF 单独导出的额外编码耗时 P90 不超过 30 秒，选择两种格式时另按实际并行或串行管线验收总时延。
- 预览进入稳定播放后的交互响应不超过 100 ms。
- 最终 MP4 文件目标不超过 15 MB。
- 标准 GIF 文件目标不超过 15 MB，超过时必须在降帧、降尺寸或只保留 MP4 之间让用户选择。
- 主流 iPhone Safari 与桌面浏览器播放候选、操作表单、查看进度和保存成片时不崩溃、不黑屏。
- 典型任务首次渲染成功率不低于 95%，阶段重试后不低于 99%。
- MP4 在主流 iPhone Safari 中完成下载或打开系统分享菜单的成功率目标不低于 98%。

### 19.2 视觉与动态质量

- 100% 成片通过四项“非视频套框”否决门槛。
- 首帧、落版帧和至少两个中间抽样帧都具有成立的杂志构图。
- 高置信度清晰正脸至少 99% 不被无意裁切或文字遮挡。
- 低置信度分割样本 100% 触发安全降级。
- 最终成片不得改变人物五官或真实动作含义。
- 主标题在至少 80% 播放时长内保持完整可读。
- 同一时刻不得有超过两个争抢注意力的动态区。
- 首尾闭环无黑帧、明显硬跳、严重重影或主体瞬移。
- 3 个候选不能只是更换滤镜、颜色和字体。
- 静态 JPG 封面与 MP4 落版帧的布局、文字和裁切一致。

### 19.3 可靠性与成本

- 上传、规范化、分析、规划、预览、高清、审核均有独立状态与重试。
- 高成本分割或 AI 生成失败时可以降级，不阻断基础动态封面。
- 先生成低清候选，用户确认后才生成高清。
- 重试不得重复扣除额度或重复生成成功资产。
- 生成任务、媒体处理和文件清理均有可审计记录。

## 20. 本地网站 MVP 验收标准

1. 启动脚本同时显示 `127.0.0.1` 本机地址和至少一个可用局域网地址。
2. iPhone 与电脑连接同一可信 Wi-Fi 后，可以通过 Safari 打开网站首页和健康检查接口。
3. 360 像素宽手机屏幕无需横向滚动，上传、选择、生成、状态和下载主操作均可单手触达，按钮触控高度不低于 44 像素。
4. 用户可以上传浏览器可解码的照片、GIF、MP4、MOV、M4V 或 WebM，单文件硬上限 100 MB；不支持类型和超限文件在渲染前给出明确错误。
5. 用户选择静态照片或 Safari 只返回 Live Photo 的 HEIC/JPG 静态版本时，网站立即预览并显示文件名、格式和大小；页面必须明确标记“当前文件没有动作”“仅静态”，主按钮显示“只生成静态 JPG”，同时显示“照片 App → … → 存储为视频”的完整动态保留步骤；不能解码时显示占位和明确错误。
6. 由 Live Photo“存储为视频”得到的文件可以上传、预览和完成动态输出，真实动作不会退化为静态首帧。
7. 网页不宣称读取了原生 `PHAsset`、静态原图、配对 MOV 或原始 Live Photo 元数据。
8. 素材、日志和结果只写入电脑上的 Git 忽略运行目录，浏览器页面和服务均不调用云端上传接口。
9. 页面明确提示本地服务没有账号和访问密码，只能在可信局域网使用、不得映射公网并应在完成后关闭。
10. 每个任务使用随机不可预测标识和独立目录，用户原始文件名不能决定服务器磁盘路径。
11. 用户可以用内置示例视频在不上传文件的情况下验证完整流程。
12. 用户可以选择先锋动态封面、斜切破版、三时态切片，或同时生成三版。
13. 照片模式只导出 JPG；视频/GIF 模式可以选择只导出 MP4、只导出 GIF 或同时导出两种动态格式，并始终获得 JPG 封面。
14. MP4 可选择高清优先或节省空间；切换格式或质量不会更改原素材。
15. 渲染在电脑单工作线程异步执行，页面显示排队、运行、完成、失败和真实阶段进度，不因一个长任务阻塞状态接口。
16. 手机锁屏、Safari 进入后台或页面刷新后，电脑渲染继续；重新打开网站可以从最近任务恢复状态和结果。
17. 渲染失败时页面显示可理解的阶段与错误，不把失败任务显示为完成。
18. 输出文件支持 HTTP Range；MP4 能在 iPhone Safari 与桌面浏览器播放、暂停和拖动。
19. 生成结果明确标记“会动 · MP4”“会动 · GIF”或“静态 · JPG”，同时提供“打开并保存”“下载到‘文件’”和对应的 iPhone 存储步骤，不依赖开发者工具或电脑文件系统操作。
20. 每个动态候选必须通过暂停、结构、时间和候选差异四项否决测试，不能只做居中视频矩形加边框。
21. 落版帧单独导出后仍是一张完整、可读的杂志封面。
22. 动作必须与刊头、文字、版心、前后景或时间切片发生关系。
23. 成片长度为 4～8 秒，默认 6 秒，1 秒内出现主动态。
24. 主标题在至少 80% 时长内保持完整可读。
25. 首尾回到同一落版状态，无黑帧、明显硬跳、严重鬼影或主体瞬移。
26. 同一时刻最多 1 个主动态区和 1 个弱辅助动态区。
27. 高置信度清晰正脸至少 99% 不被无意裁切或遮挡；人物分割质量不足时必须安全降级。
28. 低清预览、MP4、GIF 与 JPG 的片段、裁切、层级、字体和换行保持一致。
29. MP4 为 1080 × 1350、30 fps、H.264 High、`yuv420p`、BT.709、`faststart`；标准 GIF 为 720 × 900、15 fps、最多 256 色；两者默认静音。
30. 典型 6 秒 MP4 与标准 GIF 均以 15 MB 为目标上限；高清 MP4 不使用低清预览或 GIF 作为渲染源。
31. 同一素材、选项、字体与渲染器版本可以确定性重现相同结果。
32. 输入照片和最终 JPG 完成格式与完整解码检查；输入视频/GIF 和最终 MP4/GIF/JPG 完成格式与完整解码检查，动态素材不能只检查首帧。
33. iPhone Safari、macOS Safari、Chrome 至少各覆盖一次上传、生成、刷新恢复、预览和下载流程。
34. 至少使用 10 张不同 iPhone Live Photo 转出的视频，覆盖本地原件、iCloud 原件、横竖屏、明暗场景和不同动作。
35. 真机覆盖“普通照片→JPG、Live Photo 转视频→MP4/GIF/JPG、普通视频→MP4/GIF/JPG、GIF→MP4/GIF/JPG”四条主路径。
36. 从测试账号手动发布 MP4/GIF 到测试朋友圈，回看记录压缩、裁切、封面、文字、方向、播放和重播表现。
37. 使用至少 20 组不同动作样片盲测，至少 80% 用户第一描述包含“杂志、封面或动态海报”。
38. 盲测中描述为“视频套模板、加边框”的比例不超过 20%。
39. 至少 80% 用户能在 5 秒内指出作品的视觉主角。
40. 本地网站通过后再评估云端化、原生 iOS App 或微信小程序，不以未来平台能力代替当前网页验收。

## 21. 暂不进入 MVP

- iOS 原生 App，以及使用 PhotoKit 读取 Live Photo 静态原图与 `.pairedVideo`；作为本地网站验证后的首要平台预案。
- 将编辑结果重新封装并写回为系统原生 Live Photo。
- Android App，以及各厂商 Motion Photo 的专项读取。
- 微信小程序内原生读取 Live Photo；标准小程序接口不能获得完整成对资源。
- 多段视频、多轨时间线和超过一个主要视频素材。
- 9:16、1:1、横版等多比例同时首发。
- 保留原声、音乐、节拍卡点和配音。
- 无限自由提示词。
- 生成或改变人物动作、面容、服饰和身体结构。
- 复杂关键帧、任意图层、贴纸商城和专业视频编辑能力。
- 静默或自动替用户发布朋友圈。
- 公开作品社区、多人协作和复杂会员系统。

## 22. 请用户重点审核的产品决定

| 审核项 | 当前建议 |
| --- | --- |
| 核心产品 | 单个杂志封面；照片生成静态 JPG，视频/GIF 生成动态版本 |
| 首发平台 | 电脑本地网站＋手机同一 Wi-Fi 访问；无云端依赖 |
| MVP 输入 | 1 张照片、1 段 3～30 秒短视频，或 1 个受限制 GIF |
| Live Photo | 静态版本可生成 JPG；保留动作仍使用 iPhone“存储为视频”桥接 |
| 原生 Live Photo | PhotoKit 成对读取保留为后续 iOS App 预案 |
| 高光流程 | 视频推荐高光并默认选中最佳；短 GIF 默认整段，长 GIF 推荐 1～3 个 |
| 动态候选 | 可选择单版快速生成，或同时生成 3 个结构性差异方案 |
| 输出比例 | 4:5 竖版 |
| 输出文件 | 照片只输出 JPG；动态素材选择 MP4、GIF 或两者并附 JPG，默认推荐高清 MP4 |
| 首发结构 | 动态封面、主体破版、时间切片 |
| 首发视觉 | 先锋刊头、人文特刊、城市画报 |
| 人物处理 | 只编辑真实动态，不生成或修改人物面容与动作 |
| 音频 | MVP 默认移除，第二阶段再考虑原声和音乐 |
| 朋友圈发布 | MP4 保存后由用户自行发布；GIF 是否保留动画及自动播放、重播、封面和压缩均由平台决定 |
| 原素材期限 | 默认 24 小时；主动删除后访问立即失效，活动文件 24 小时内清除 |
| 结果期限 | 默认 7 天；主动删除后访问立即失效，备份最迟 30 天清除 |
| AI 标识 | 按法规和平台要求保留，不提供关闭开关 |
| 商业模式 | MVP 暂不收费，先验证动态海报质量与分享完成率 |
