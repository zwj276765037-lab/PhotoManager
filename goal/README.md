# 项目需求与功能要求

## 1. 项目目标

开发一个微信小程序，让用户主动导入照片，并通过相册、标签、日期等方式完成管理与分类。产品首先保证流程简单、数据隔离和可恢复，再逐步加入智能分类。

## 2. MVP 功能范围

### 2.1 用户与数据隔离

- 用户进入小程序后建立匿名业务身份，照片记录必须与当前微信用户绑定。
- 用户只能读取、修改和删除自己的照片及分类数据。
- 管理端能力不进入首个用户版本。

### 2.2 照片导入

- 用户可从相册主动选择照片，也可直接拍摄。
- 支持一次导入多张照片，并显示上传进度、成功数和失败原因。
- 对格式、单文件大小、一次选择数量设置明确限制。
- 不承诺、也不尝试在后台静默读取用户的整个系统相册。

### 2.3 存储与索引

- 原图与缩略图存放在文件/对象存储中。
- 数据库保存照片索引，不直接保存图片二进制。
- 最小照片记录建议如下：

```text
photoId, ownerId, originalFileId, thumbnailFileId,
width, height, size, importedAt, capturedAt,
albumIds, tags, classifyStatus, deletedAt
```

- 删除优先采用“回收站 + 延迟清理”，避免用户误删后无法恢复。

### 2.4 分类与管理

- 按导入日期或可获得的拍摄日期分组。
- 用户可创建、重命名和删除相册。
- 一张照片可加入多个相册，并可添加多个标签。
- 支持照片预览、批量选择、移动/加入相册、修改标签和移入回收站。
- 首版搜索至少支持相册名和标签；更复杂的语义搜索后续开发。

### 2.5 智能分类（第二阶段）

- 场景/物体分类、OCR 等计算应放在云函数或后端异步执行。
- AI 返回的是建议标签，用户可以确认、修改或忽略。
- 人脸检测、聚类或识别涉及更高隐私与合规风险，必须单独评审需求、授权、数据保存和平台规则后再启用。

## 3. 非功能要求

- 隐私：只收集功能必需的数据；在导入、云端处理和删除规则上向用户说明。
- 安全：服务端校验用户身份和资源所有权，不能只依赖前端传入的 `ownerId`。
- 性能：列表使用缩略图、分页和懒加载，不直接批量加载原图。
- 可靠性：上传失败可重试；数据库记录与文件上传需处理半成功状态。
- 成本：限制原图大小、缩略图规格和云端 AI 调用频率，并设置用量告警。
- 可维护性：关键逻辑有测试或可复现的手工验证步骤，配置与密钥不能提交到 Git。

## 4. MVP 验收标准

- 新用户能够主动选择并成功上传至少一张受支持的照片。
- 上传后能在照片列表看到缩略图和导入时间。
- 用户能够新建相册、把照片加入相册并通过相册查看。
- 用户能够添加/删除标签，并通过标签筛选照片。
- 用户能够把照片移入回收站并恢复。
- 用户甲无法访问用户乙的照片记录或文件。
- 上传失败、无权限、网络中断和存储不足等常见异常有可理解的提示。
- 真机测试通过，并完成隐私保护指引与实际数据处理行为核对。

## 5. 首轮待确认事项

- 首版是否只使用微信云开发，还是已有独立服务器与已备案域名。
- 是否保留原图，还是允许用户选择压缩存储以节省费用。
- 回收站保留天数与单用户存储上限。
- 智能分类的优先方向：场景/物体、OCR、相似照片、重复照片或人物聚类。
- 小程序面向个人内部使用、公开用户，还是特定组织成员。
