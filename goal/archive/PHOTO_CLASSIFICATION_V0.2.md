# PhotoManager 项目需求与功能要求

> 归档说明：该版本是“大量照片管理与分类”方向的需求稿。项目已于 2026-08-29 转向“AI 朋友圈照片拼图”，本文件仅保留历史决策，不再作为当前开发目标。

> 版本：v0.2-draft
>
> 状态：待用户审核
>
> 更新时间：2026-08-29
>
> 本轮主题：大量照片导入、预览去重、重命名、建立多个相册、按时间与地点分类

## 1. 产品目标

PhotoManager 是一个微信小程序照片整理工具。用户主动从手机相册分批选择大量照片，在正式归档前完成预览、精确去重、重命名和分类方案确认，再一次建立或更新多个 PhotoManager 相册。

核心目标如下：

- 将“大量照片选择”组织成一个可持续追加、可恢复的导入任务。
- 在正式分类前提供照片总览和重复照片处理，避免先导入再返工。
- 支持单张重命名和批量规则重命名，并实时预览结果。
- 支持手动分类、按拍摄时间分类、按拍摄地点分类及组合分类。
- 分类结果正式生效前，允许用户检查、改名、合并、拆分和移动照片。
- 一份云端照片可以属于多个逻辑相册，但原文件只保存一份。
- 所有操作默认只影响 PhotoManager 云端资料库，不修改用户手机中的原照片。

## 2. 必须明确的平台边界

### 2.1 “选择整个手机相册”的可实现定义

纯微信小程序不能静默扫描、枚举或一次性读取用户整个手机相册。照片必须由用户打开系统选择器并主动选择。

微信官方 `wx.chooseMedia` 接口目前的数量限制为：

- 基础库低于 2.25.0：一次最多选择 9 个文件。
- 基础库 2.25.0 及以上：一次最多选择 20 个文件。
- 实际能力还可能受到微信版本、手机系统和机型限制。

因此，本项目将“大量照片”定义为：用户在同一个导入任务中反复点击“继续添加”，每次选择一批照片，系统累计全部批次后统一预览和整理。

首版建议以单个任务累计 200 张照片作为验收基线，完成真机压力测试后再把可配置上限提高至 500 张。它不等于系统选择器一次选择 200 或 500 张。

如果未来“一键读取整册或数千张照片”是不可妥协的硬需求，则需要增加原生 App、PC/Web、ZIP 或云盘导入入口，不能只依赖微信小程序完成。

### 2.2 重命名和建立新相册的范围

- “重命名”是修改 PhotoManager 中的照片显示名称，不修改手机系统相册里的原文件名。
- “建立新相册”是在 PhotoManager 中建立虚拟相册，不在手机系统相册中建立原生相册。
- “移动照片”是修改照片与 PhotoManager 相册之间的关联，不移动手机原文件。
- “去重”只决定是否导入、复用或删除 PhotoManager 云端副本，不删除手机相册里的原图。

所有页面文案都必须写清“小程序内名称”“PhotoManager 相册”或“云端照片”，不得让用户误以为正在直接修改手机系统相册。

### 2.3 时间和地点信息的限制

微信选图接口不直接返回原文件名、拍摄时间或 GPS。系统只能对用户选择的原文件尝试解析 EXIF 元数据：

- 有有效 EXIF 拍摄时间时，才能自动按真实拍摄时间分类。
- 有有效 EXIF GPS 时，才能通过逆地理编码自动按拍摄地点分类。
- 截图、下载图、社交软件转发图、编辑图或被清除元数据的照片可能没有时间和地点。
- 不得用用户当前手机定位冒充历史照片的拍摄地点。
- 元数据缺失或解析失败时，必须进入“未知时间”或“未知地点”，并允许用户单张或批量补充。

因此，“按时间/地点分类”是尽力识别并可人工修正的功能，不承诺所有照片都能自动获得真实拍摄时间和地点。

## 3. 核心术语

| 名称 | 定义 |
| --- | --- |
| 手机系统相册 | iOS/Android 管理的本机照片库，PhotoManager 只能让用户主动选择其中的照片 |
| PhotoManager 资料库 | 用户在小程序云端拥有的私有照片集合 |
| 导入任务 | 一次从多轮选择开始，到预览、去重、分类并正式保存结束的完整流程 |
| 临时区 | 为生成缩略图、解析元数据和去重而使用的私有暂存空间，尚不算正式导入 |
| 虚拟相册 | PhotoManager 内的逻辑分组，一张照片可以属于多个虚拟相册 |
| 精确重复 | 文件内容完全相同，可通过可靠内容哈希确认 |
| 相似照片 | 内容相近但文件不完全相同，例如连拍、压缩、裁剪或调色后的照片 |
| 显示名称 | PhotoManager 内展示的名称，不改变手机原文件名 |

## 4. 完整用户流程

```text
首次使用与隐私说明
        ↓
新建导入任务
        ↓
多轮选择并继续添加照片
        ↓
选择结果预览（增删、排序、查看大图）
        ↓
私有临时上传与预处理
        ↓
重复照片预览与处理
        ↓
单张或批量重命名
        ↓
选择手动、时间、地点或组合分类规则
        ↓
预览将新建/更新的多个相册
        ↓
调整相册名、合并/拆分分组、移动照片
        ↓
最终确认并正式保存
        ↓
查看成功、复用、跳过和失败结果
```

任务状态定义如下：

```text
草稿 → 选择中 → 暂存中 → 分析中 → 去重待确认
     → 规则配置中 → 方案待确认 → 执行中
     → 完成 / 部分失败 / 已取消 / 已过期
```

用户确认分类方案前，不建立或修改用户可见的正式相册。若为了去重与 EXIF 解析需要临时上传，必须提前说明用途和清理期限。

## 5. 详细功能需求

### 5.1 首次使用与隐私说明

首次进入整理流程时，系统必须说明：

- 只有用户主动选择的照片才会被读取。
- 手机中的原照片不会被改名、移动或删除。
- 所选照片可能被临时上传，用于缩略图、EXIF 解析和精确去重。
- 拍摄时间和 GPS 可能被提取并用于分类；若调用地图服务，需要说明第三方处理情况。
- 云端照片、缩略图和位置索引的保存期限及删除方式。
- 用户拒绝非必要权限后，仍能使用不依赖该权限的功能。

用户尚未同意适用的隐私保护指引时，不得调用照片选择接口。

### 5.2 首页与导入任务

首页至少提供：

- “开始整理照片”主入口。
- 未完成任务入口，展示已选数量、当前阶段和最后更新时间。
- “所有照片”“相册”“待处理”“回收站”入口。
- 当前云端用量与剩余空间提示。

新建任务时生成唯一 `taskId`。同一用户可以保留未完成任务，但首版同一时间只允许一个任务执行上传或正式保存，避免资源竞争。

### 5.3 多轮选择大量照片

选择流程要求：

1. 用户点击“从手机相册选择”。
2. 小程序调用系统照片选择器，单轮按当前平台允许的最大数量选择。
3. 返回任务页后显示本轮新增数、累计数、异常数和预计空间。
4. 用户可以点击“继续添加”重复上述步骤。
5. 用户取消某一轮选择或拒绝授权时，之前已加入任务的照片不丢失。
6. 达到任务上限时停止继续添加，并明确说明可先完成本任务再新建下一任务。

任务列表必须使用缩略图、分页或虚拟列表，不能一次把全部原图加载到内存。

建议默认限制（待审核）：

- 验收基线：单任务累计 200 张。
- 规划上限：完成压力测试后支持 500 张，可按设备能力和云端配额配置。
- 单张大小：首版建议 20 MB，最终以真机、云存储和上传接口验证结果为准。
- 支持类型：MVP 先支持常见静态图片；视频、Live Photo、RAW、动图的完整支持后续单独定义。

### 5.4 选择结果预览

进入预处理前，用户可以：

- 查看累计选择的全部缩略图与总数。
- 点击缩略图全屏预览原图或可用清晰图。
- 按选择顺序、可获得的时间和名称排序。
- 单选、多选或全选照片后移出当前任务。
- 查看文件大小、尺寸、格式以及目前能够获得的名称。
- 回到选择器继续添加照片。

从任务移除只影响当前导入草稿，不删除手机原图。

### 5.5 临时上传与预处理

用户点击“开始扫描整理”后，系统进行私有暂存和分析：

- 生成列表用缩略图。
- 读取尺寸、格式和文件大小。
- 尽力读取原始文件名；无法读取时生成内部默认名。
- 尝试解析 EXIF 拍摄时间、时区、方向和 GPS。
- 计算精确内容哈希。
- 检查本任务内和用户现有资料库中的重复照片。
- 标记损坏、不支持、超限或读取失败的文件。

临时文件默认建议在任务取消或过期后 24 小时内清理。临时路径不能作为长期照片地址；每张照片必须记录上传、分析、失败和重试状态。

进入暂存后的成功项目应支持关闭小程序后继续恢复。尚未暂存且本机临时文件已被微信清理的项目，应提示用户重新选择，不得显示虚假成功。

### 5.6 去重预览

去重发生在正式分类之前，并分为两个等级。

#### 5.6.1 精确重复（MVP）

精确重复使用可靠内容哈希确认，不能只比较文件名、大小或拍摄时间。

- 本任务内完全相同：默认保留一份，其余标记“本次跳过”。
- 与资料库已有照片完全相同：默认复用已有云端原文件，只新增所需的相册关联，不再次保存原图。
- 用户可以逐组改变保留项，也可以选择“全部保留”。
- 默认推荐保留文件完整、分辨率更高或已存在资料库中的资产。
- 任何自动建议在用户确认前都不能执行永久删除。

#### 5.6.2 相似照片（第二阶段）

裁剪、压缩、连拍、截图、调色后的照片只能标记为“可能相似”。后续可使用感知哈希或视觉模型分组，但必须：

- 显示“相似建议”，不得当作完全重复。
- 不得默认自动删除或跳过。
- 允许并排预览、放大细节和人工决定保留项。

去重页面至少展示：重复组数、每组照片、判定类型、资料库已有项、建议保留项、预计节省空间。所有操作只影响 PhotoManager 导入方案，不删除手机原图。

### 5.7 重命名

支持以下方式：

- 保留原名称。
- 单张修改显示名称。
- 多选照片设置相同前缀或后缀。
- 使用模板批量重命名。
- 执行前实时预览全部结果。
- 名称冲突时自动增加稳定序号，或提示用户手动处理。
- 永久保留原始名称字段，方便查看和以后导出。

建议支持的模板变量：

| 变量 | 含义 | 示例 |
| --- | --- | --- |
| `{original}` | 可获得的原始名称 | `IMG_1234` |
| `{YYYY}{MM}{DD}` | 拍摄日期 | `20260829` |
| `{HH}{mm}{ss}` | 拍摄时间 | `153025` |
| `{country}` / `{province}` / `{city}` | 解析后的地点 | `杭州` |
| `{album}` | 目标相册名称 | `杭州旅行` |
| `{index}` | 按当前排序生成的序号 | `001` |

示例：

```text
杭州旅行_20260829_001
杭州旅行_20260829_002
```

默认按拍摄时间排序后编号；没有拍摄时间的照片排在最后。MVP 建议一张照片在资料库中只有一个全局显示名称，即使它属于多个相册也不产生多个名称版本。

### 5.8 分类方式

#### 5.8.1 手动分类

- 用户可一次新建一个或多个相册。
- 可将一张或多张照片加入一个或多个相册。
- 一张照片加入多个相册时只保存一份云端原文件。
- 用户可建立“未分类”分组，稍后继续整理。

#### 5.8.2 按时间分类

时间来源优先级：

1. EXIF 原始拍摄时间。
2. 能够可靠获得的文件时间。
3. 本次导入时间，仅作为明确标注的后备值。

分类粒度：

- 年，例如 `2026年`。
- 年/月，例如 `2026年08月`，建议作为默认值。
- 年/月/日，例如 `2026年08月29日`。

规则要求：

- 每张照片都显示采用的时间值和来源。
- 非 EXIF 时间必须标记为“推测时间”。
- 没有有效时间的照片进入“未知时间”。
- 用户可以单张或批量修正时间后重新生成分类预览。
- 对未来时间、明显错误年份和缺失时区进行异常提示，不擅自篡改原值。

#### 5.8.3 按地点分类

自动地点分类只使用照片自身的 EXIF GPS，并通过地图服务转换为地名。

可选粒度：

- 国家。
- 省/州。
- 城市，建议作为默认值。
- 区/县。

规则要求：

- 没有 GPS、GPS 无效或逆地理编码失败的照片进入“未知地点”。
- 用户可以为单张或多张照片手动指定地点。
- 不能用 `wx.getLocation` 获得的当前设备位置自动替代历史拍摄地点。
- 若提供“标记为当前位置”，必须由用户主动触发并清楚标注来源。
- 调用第三方地图服务前，需在隐私说明中披露坐标的处理方式。

#### 5.8.4 时间与地点组合分类

支持两种组合模式：

1. 嵌套分类：例如 `2026年 → 杭州市` 或 `杭州市 → 2026年08月`。
2. 平行分类：同时生成一套时间相册和一套地点相册，同一照片可出现在两套相册中。

建议 MVP 默认使用嵌套分类，避免一次生成过多相册。用户必须能在预览中看到一张照片将被加入哪些相册。

通用分类规则：

- 已存在同路径、同名称相册时，默认合并到已有相册并明确标识。
- 不创建没有照片的空相册。
- 一次计划生成超过 100 个相册时提示降低分类粒度。
- “未知时间”“未知地点”始终可见，不得丢弃元数据不完整的照片。

### 5.9 多相册分类方案预览

最终确认前必须提供独立预览页，此时正式相册尚未创建或修改。

预览页展示：

- 将新建多少个相册、更新多少个已有相册。
- 每个相册的名称、路径、封面和照片数量。
- 新增照片、复用已有照片、跳过重复照片和失败照片的数量。
- 未知时间、未知地点和待人工处理的数量。
- 预计新增云端空间。
- 每张照片将加入的全部相册。

用户可以在预览中：

- 修改新相册名称。
- 决定同名相册是合并还是创建带序号的新相册。
- 合并两个建议分组。
- 从分组中移出照片或将照片移动到另一分组。
- 为照片追加第二个或更多相册。
- 修改照片时间、地点或名称，并重新生成结果。
- 返回去重页面改变保留决定。
- 修改分类粒度并重新预览。

每次调整后，相册数量、封面、照片数和空间估算必须同步更新。

### 5.10 确认执行、进度与结果

用户点击“确认创建相册”后才正式执行。执行要求：

- 按照片显示待处理、分析中、已上传、已复用、已建索引、已跳过或失败状态。
- 显示总进度、成功数、复用数、跳过数和失败数。
- 网络中断后允许继续或仅重试失败项目。
- 部分失败时保留成功结果，不重复上传已经成功的照片。
- 取消操作只停止尚未提交的项目，已经正式保存的项目在结果页中如实列出。
- 重复点击确认、重新进入页面或网络重试不得创建重复照片、相册或关联。

完成页提供：

- 查看新建相册。
- 查看失败项目及具体原因。
- 重试失败项目。
- 继续整理下一批。
- 导出本次任务结果摘要。

### 5.11 资料库、相册和删除

资料库至少包含：所有照片、相册、未分类、未知时间、未知地点、最近导入和回收站。

必须区分以下操作：

- “从相册移除”：只删除照片与该相册的关联，照片仍在资料库或其他相册中。
- “删除 PhotoManager 照片”：将云端照片移入回收站，并提示它同时属于多少相册。
- “跳过重复项”：只是不导入当前选中的副本。
- “删除相册”：默认只删除相册及关联，不删除相册内照片。

建议云端回收站默认保留 30 天。到期彻底删除时，需要清理原图、缩略图、EXIF 索引、相册关联及其他派生数据。以上操作均不影响手机原图。

## 6. 数据模型建议

### 6.1 PhotoAsset（照片资产）

```text
photoId, ownerId,
originalFileId, thumbnailFileId,
originalName, displayName,
contentHash, mimeType, size, width, height,
capturedAt, capturedAtSource, timezone,
gps, locationText, locationSource,
importedAt, status, deletedAt
```

### 6.2 Album（虚拟相册）

```text
albumId, ownerId, parentAlbumId,
name, coverPhotoId, sourceType,
createdAt, updatedAt, deletedAt
```

### 6.3 AlbumPhoto（照片与相册关联）

```text
relationId, ownerId, albumId, photoId,
sortOrder, addedAt
```

### 6.4 ImportTask / ImportItem（导入任务与项目）

```text
taskId, ownerId, taskStatus, selectedCount,
successCount, reusedCount, skippedCount, failedCount,
renameRule, classifyRule, expiresAt, createdAt, updatedAt

itemId, taskId, photoId, stagedFileId,
contentHash, duplicateType, itemStatus,
errorCode, retryCount
```

服务端必须从可信身份获得 `ownerId`，不能直接相信前端传入的所有者字段。

## 7. 异常与边界情况

必须设计并验证以下情况：

- 用户不同意或撤销隐私授权。
- 某一轮取消选择，但任务中已有照片需要保留。
- 用户多轮选择到同一张照片。
- 小程序进入后台、被系统终止或临时文件被清理。
- Wi-Fi 切换为移动网络、网络断开或上传超时。
- 云端存储空间不足或用户达到配额。
- 文件过大、损坏、格式不支持或 EXIF 读取失败。
- 社交软件压缩后时间与地点信息丢失。
- 拍摄时间是未来日期、异常年份或相机时钟错误。
- GPS 无效、地点在海上或逆地理编码失败。
- 不同照片具有相同名称。
- 相册同名或嵌套路径冲突。
- 一张照片同时属于多个相册。
- 预览过程中用户改变规则或移除照片。
- 执行中重复点击确认、刷新或重新进入页面。
- 任务过期、取消或部分失败。
- 用户删除账号并要求彻底清理数据。

每类错误都应提供可理解的原因和下一步操作，不能只显示“操作失败”。

## 8. 非功能要求

### 8.1 隐私与安全

- 照片、缩略图、EXIF 时间、GPS 和分类结果默认仅所属用户可访问。
- 不生成永久公开文件链接；预览使用有时效的授权地址。
- 服务端、数据库和文件存储都必须校验资源所有权。
- 只收集功能必需的数据，并提供查看、更正、导出和彻底删除入口。
- 第三方地图或 AI 服务必须在隐私说明中披露实际传输的数据和用途。
- 密钥、令牌、真实用户数据和生产配置不得提交到 Git。

### 8.2 性能

- 大列表只加载缩略图并分页/虚拟渲染。
- 上传并发数根据网络和设备能力限制，避免内存峰值。
- 200 张照片的选择、预览和任务恢复不得导致页面崩溃。
- 原图按需加载，不能在列表页批量下载。

### 8.3 可靠性

- 导入任务和正式确认操作必须幂等。
- 上传失败支持有限次数自动重试和用户手动重试。
- 文件上传、数据库索引和相册关联需要处理半成功状态。
- 成功、复用、跳过、失败数量之和必须能与任务总数核对一致。

### 8.4 成本

- 执行前估算新增云端空间。
- 精确重复照片优先复用已有原文件。
- 限制单张大小、任务数量、缩略图规格和第三方地图调用频率。
- 设置存储、流量和云函数用量告警。

## 9. MVP 范围与后续范围

### 9.1 MVP 必须包含

- 微信用户身份和私有数据隔离。
- 同一任务多轮选择并累计大量照片。
- 缩略图预览、移出任务和大图查看。
- 私有暂存、进度、失败重试和任务恢复。
- 精确重复识别及与已有资料库资产复用。
- 单张与批量模板重命名。
- 手动、时间、地点和时间地点组合分类。
- 未知时间、未知地点的人工修正。
- 建立多个相册前的完整方案预览与调整。
- 所有照片、相册、最近导入和回收站。

### 9.2 暂不进入 MVP

- 自动扫描或一次性读取整个手机相册。
- 修改、移动或删除手机系统相册中的原照片。
- 创建手机系统原生相册。
- 自动删除相似照片。
- 人脸识别、人物聚类、AI 场景分类和 OCR。
- 视频、Live Photo、RAW 的完整管理。
- 共享相册和多人协作。
- PC/Web/云盘整库导入入口。

## 10. MVP 验收标准

1. 用户未主动选择照片时，小程序不能读取或扫描手机相册。
2. 基础库 2.25.0 及以上单轮最多选择 20 张，低版本降级为最多 9 张，并能继续添加到同一任务。
3. 用户取消某一轮或拒绝授权后，之前已加入任务的照片不丢失。
4. 基准测试机累计处理 200 张照片时，预览页不崩溃、不卡死且不批量加载原图。
5. 正式确认前不建立用户可见的正式相册；临时上传的用途和清理期限已明确告知。
6. 本任务内完全相同的文件可以被识别为精确重复，并默认只保留一份。
7. 与资料库已有文件完全相同时，默认复用已有云端资产，不重复保存原图。
8. 相似照片只能作为建议，未经用户确认不得自动删除或跳过。
9. 去重、重命名、移出任务和删除云端照片均不改变手机原图。
10. 批量命名预览与正式执行结果一致，名称冲突具有稳定且唯一的后缀。
11. 时间分类优先使用 EXIF 拍摄时间，每张照片可以查看时间来源。
12. 地点分类只使用照片 EXIF GPS，不使用当前定位冒充历史拍摄地点。
13. 缺少时间或地点的照片分别进入可见的“未知时间”“未知地点”，并可人工修正。
14. 分类预览能准确展示将新建、更新、复用、跳过和失败的数量。
15. 用户能够在执行前修改相册名称、合并分组、移动照片和改变分类粒度。
16. 一张照片加入多个相册时，云端只保存一份原文件。
17. 删除相册默认不删除照片，从一个相册移除照片不影响其他相册。
18. 网络中断或重复确认不会产生重复照片、重复相册或重复关联。
19. 部分失败可以单独重试失败项目，已成功项目不会重复执行。
20. 用户关闭并重新进入小程序后，已完成暂存的任务项目可恢复；丢失的未暂存临时文件会提示重新选择。
21. 图片、缩略图、EXIF 和 GPS 默认只有所属账号能够访问。
22. 用户可以彻底删除云端原图、缩略图、元数据索引和相册关联。
23. Android 与 iOS 真机均完成多轮选择、去重、分类、失败重试和删除流程验证。

## 11. 请用户重点审核的产品决定

以下默认值尚未最终确认：

| 审核项 | 当前建议 |
| --- | --- |
| 大量照片的实现 | 接受“同一任务多轮选择累计”，不承诺一次读取整册 |
| 单任务验收数量 | MVP 先稳定处理 200 张，再评估提高到 500 张 |
| 相册含义 | 仅指 PhotoManager 云端虚拟相册 |
| 重命名含义 | 仅修改 PhotoManager 内全局显示名称，保留原始名称 |
| 原图质量 | 默认保存用户选择的原图；如成本过高再提供压缩选项 |
| 去重范围 | MVP 做精确重复；相似照片检测进入第二阶段 |
| 重复照片默认操作 | 任务内保留一份；资料库已有时复用已有原文件 |
| 时间默认粒度 | 按月 |
| 地点默认粒度 | 按城市 |
| 时间 + 地点 | 默认使用嵌套相册，可选平行生成两套相册 |
| 同名相册 | 默认合并到已有相册，预览页可改为新建 |
| 临时任务清理 | 取消或过期后 24 小时内清理 |
| 回收站期限 | 默认 30 天后彻底删除 |
| 后端方案 | MVP 优先使用微信云开发 |
