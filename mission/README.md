## 2026-08-29 11:29 CST — 完成动态双输入双输出与高清无损母版管线

- 类型：输入输出扩展 / 画质修复 / FFmpeg 渲染 / 可播放验证 / 文档
- 优化内容：
  - 根据用户确认，将 MVP 固定为“视频或 GIF 动态图片输入；MP4、GIF 或两者输出；始终附 JPG 封面”。
  - 新增 360 × 640、49 帧、4.08 秒的真实多帧 GIF 测试输入；实际覆盖视频→MP4、视频→GIF、GIF→MP4、GIF→GIF 四条路径。
  - `render_demo.py` 新增 `--format mp4|gif|both`、`--quality high|standard` 和单版式选择；高清 MP4 默认使用 H.264 CRF 14，节省空间档使用 CRF 19。
  - 修复 GIF 输入先转有损 H.264、GIF 输出再经过有损 MP4 的多余压缩：GIF 输入改用保持原尺寸的 FFV1 4:4:4 临时时间轴，版式只渲染一次 FFV1 无损 4:4:4 母版，再分别编码 MP4、GIF 与 JPG。
  - 视频和 GIF 的每个版式分支直接从源尺寸按最终视窗宽高比完成一次目标裁切/缩放，不先统一放大后再次缩小；避免高分辨率输入先固定降到 720 像素后重新放大，并统一写入 1:1 像素宽高比。
  - 统一无损母版为 BT.709 limited；MP4 显式降采样为兼容型 `yuv420p`，GIF 显式转 RGB 调色板，JPG 显式转换为常规 JFIF 使用的 BT.601 full，避免跨格式色彩矩阵误读。
  - 高清三版 MP4 实际为 4,556,967 / 2,417,913 / 2,774,726 字节；CRF 19 动态封面对照为 2,393,601 字节；GIF→MP4 为 4,505,434 字节；视频→GIF 为 14,265,706 字节；GIF→GIF 为 6,916,455 字节，均低于 15 MB 目标。
  - 更新本地对比页，加入四条输入输出路径、CRF 19/14 像素对比和清晰度解释。原片视频流只有约 646 kb/s，且存在夜景运动模糊；720 像素宽源生成 1080 像素宽版面仍需放大 1.5 倍，高清编码只能减少二次损失，不能恢复源片没有记录的细节。
- 验证：四条路径均完成真实渲染；所有 MP4/GIF 完整逐帧解码，MP4 为 1080 × 1350、6 秒、180 帧、30 fps、H.264 High、`yuv420p`、BT.709、`faststart`，GIF 为 720 × 900、90 帧、约 6 秒、无限循环；本地对比页全部媒体引用存在；同一输入重复渲染的 MP4/GIF/JPG 哈希一致；脚本语法、Markdown 和 Git 差异检查通过。
- 未解决：原视频清晰度不代表最终高质量素材上限；第二版尚未加入逐帧人物主体蒙版；GIF 保存到 iOS/Android 后是否仍动，以及朋友圈对 MP4/GIF 的二次压缩仍需真机验证；正式微信小程序尚未接入。
- Git 提交：以本次动态双输入双输出与画质修复提交为准。
