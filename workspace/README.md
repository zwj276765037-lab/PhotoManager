# 代码工作区

`workspace/` 只存放可运行的项目代码、配置样例和测试，不存放需求讨论或过程记录。

项目进入实现阶段后，建议采用以下结构：

```text
workspace/
├── miniprogram/       # 微信小程序前端
│   ├── pages/         # 页面
│   ├── components/    # 通用组件
│   ├── services/      # 登录、照片、相册、标签等接口封装
│   ├── utils/         # 无业务状态的工具函数
│   ├── app.js
│   ├── app.json
│   └── app.wxss
├── cloudfunctions/    # 云函数；若采用自建后端则改为 server/
├── tests/             # 自动化测试或可复现测试脚本
├── project.config.json
└── README.md          # 本地开发、配置和测试说明
```

## 实现原则

- 页面层负责展示和交互，数据访问统一放在 `services/`。
- 文件上传与数据库写入需要明确状态，避免只上传文件或只创建记录的半成功数据。
- 图片列表只加载缩略图并分页，查看详情时才加载原图。
- 数据权限必须在云函数/后端与数据库规则中校验，前端校验不能作为安全边界。
- 环境 ID、域名等使用环境配置；密钥、令牌和用户数据不得提交到 Git。
- 每一个功能都要能够对应 `goal/` 中的需求和 `mission/` 中的一次记录。
