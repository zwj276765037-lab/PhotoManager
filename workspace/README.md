# 代码工作区

`workspace/` 只存放可运行的项目代码、配置样例和测试，不存放需求讨论或过程记录。

项目进入实现阶段后，建议采用以下结构：

```text
workspace/
├── miniprogram/       # 微信小程序前端
│   ├── pages/         # 页面
│   ├── components/    # 通用组件
│   ├── services/      # 登录、上传、生成任务、保存分享等接口封装
│   ├── utils/         # 无业务状态的工具函数
│   ├── app.js
│   ├── app.json
│   └── app.wxss
├── cloudfunctions/    # 登录、任务创建、状态查询等短任务
├── backend/           # 异步队列、AI 调度、内容安全与数据清理
├── renderer/          # 服务端高清拼图渲染与 AI 标识处理
├── tests/             # 自动化测试或可复现测试脚本
├── project.config.json
└── README.md          # 本地开发、配置和测试说明
```

## 实现原则

- 页面层负责展示和交互，数据访问统一放在 `services/`。
- 原图使用私有临时存储，小程序预览只加载缩略图，高清合成在服务端完成。
- 上传、输入审核、AI 分析、预览、高清渲染和输出审核均有独立状态与重试策略。
- AI 不可用时降级为普通模板拼图，核心选图和导出流程不能完全失效。
- AI 密钥、内容安全密钥和存储凭据只存在服务端。
- 数据权限必须在云函数/后端与数据库规则中校验，前端校验不能作为安全边界。
- 环境 ID、域名等使用环境配置；密钥、令牌和用户数据不得提交到 Git。
- 每一个功能都要能够对应 `goal/` 中的需求和 `mission/` 中的一次记录。
